# 動詞の判定

動詞に意味の区分を与えるモデルの判定を、モデルごとに 1 つの JSONL で置きます。1 行が 1 語です。行のフィールドの意味は `../../pipeline/votes.py` の冒頭にあります。`manifest.json` は生成の来歴です。方針の全文と 23 中項目の一覧のほか、few-shot と dspy のバージョン、母集団の作り方、パスごとの語数、生成コマンドを持ちます。

## ファイル一覧

判定の JSONL、生成の来歴、走行の記録を 1 つのディレクトリに置きます。走行の記録にあたる `run-*.log` と `failed-*.json` は、git が追跡しません。

| ファイル | 中身 |
|---|---|
| `<モデル>.jsonl` | 最初のパスの判定(種 694) |
| `<モデル>-s<種>.jsonl` | 追加のパスの判定(種 1002 と 1003) |
| `final/<モデル>.jsonl` | 多数決で決めた確定値 |
| `manifest.json` | 生成の来歴と条件 |
| `run-*.log` | 走行のログ |
| `failed-*.json` | 失敗したバッチの語 |

パスごとにファイルを分けているのは、冪等な再実行が判定済みの語を飛ばす作りだからです。同じファイルに混ぜると、2 つ目のパスの判定が飛ばされます。

## 判定の重ね方と確定

全語に 3 つのパスの判定を取ります。名詞のように日常語へ絞らないのは、母集団が 7 千語弱と小さいからです。パスごとにバッチの組み方の種を変えるのは、温度 0 ではバッチを固定すると同じ判定が出るためです。

確定値は `../../pipeline/finalize.py` が 2 つの規則で決めます。2 パス以上に現れた語では 2 パス以上が挙げた中項目だけを採り、1 パスにしか現れない語ではその判定をそのまま採ります。どちらの規則で決めたかは、確定値の `votes` と `rule` のフィールドで区別できます。

1 パスにしか現れない語は、失敗したバッチに載って残りのパスで未判定のまま終わった語です。2026-09-09 に `final/` の `rule` を数えたところ、`single-vote` は claude-haiku-4-5-20251001 の 6,768 語のうち 2 語だけで、gpt-5.6-luna の 6,751 語には 1 語もありませんでした。残りはすべて `majority` です。

どの中項目も 2 パスに届かない語は確定せず、確定値にも `../verb-semantic-class-table.tsv` にも載りません。落とした語と、2 パスに届かず落ちた中項目は、`../review/` に残ります。

## 生成の方針のバージョン

動詞の判定の行は、生成の方針のバージョンとして `contract` に `v3-reworded` を持ちます。`manifest.json` は、自身の `version` が `v5-verbs` で、判定に使った方針の版を `contract.id` に `v3-reworded` として記録します。名詞の判定が持つ `v2-corrected` との違いは文言だけなので、語義の判断基準は同じです。
