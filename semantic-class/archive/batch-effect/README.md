# バッチの組み方が判定を動かすかの対照実験

名詞ごとに意味の区分を並べた意味分類表を LLM に作らせる工程で、1 回の呼び出しにまとめる語の組み合わせが判定を動かすかを測った記録である。同じ 400 語を、バッチの組み方だけ変えた 2 つのパスで分類し、語ごとに突き合わせた。組み方は判定を動かす。claude-haiku-4-5-20251001 では、中項目の集合が一致した語は 65.0% にとどまり、バッチを固定した対照では 400 語すべてが一致した。ただし、検出器 `concrete-noun-misfit` が読む具体物の条件、つまり引けた分類の部門がすべて生産物か自然物にあるかは、95.5% で保たれた。

分類は語を 20 語ずつのバッチにまとめ、1 回の呼び出しで判定させる。バッチの中身は種を決めて混ぜてから切るため、ある語の判定が、たまたま同じバッチに載った他の語に影響される余地がある。影響されるなら、バッチの組み方を変えるだけで表の中身が変わることになる。

## 入力データ

判定に使った入力は次のとおりである。

| データ | 入手先 | バージョン・日付 | 件数 |
|---|---|---|---|
| 標本を抜く母集団 | `../../noun/inputs/jmdict-noun-headwords.txt` | 2026-08-30 | 161,855 語 |
| 抜いた標本 | 母集団から種 694 の `random.sample` | — | 400 語 |
| 分類器と few-shot | `../../noun/target.py` | `v2-corrected` | 実例 26 語 |
| モデル | `~/.env` の `ANTHROPIC_MODEL`・`OPENAI_MODEL`(外部) | `claude-haiku-4-5-20251001`・`gpt-5.6-luna` | — |

## 前提条件

この対照実験で変えたのはバッチの組み方だけである。標本の 400 語も、分類器と few-shot も、どのパスでも同じものを使い、温度 0 と用例を添えない条件は 2 つのモデルのどちらでもそろえた。バッチの組み方は種で決まるので、パスの間で違うのは種の値だけである。

対照として同じバッチの組み方でも 2 パス分類したのは、一致が下がる原因を切り分けるためである。バッチを変えたときだけ下がるなら、原因はバッチの中身にある。一方、バッチを変えなくても同じだけ下がるなら、原因はパスごとの揺れなので、バッチを小さくしても直らない。

母集団の `../../noun/inputs/jmdict-noun-headwords.txt` はリポジトリにあるので、種 694 の標本 400 語は誰でも同じものを取り出せる。一方、分類は API を呼ぶため、`~/.env` の `ANTHROPIC_MODEL` と `OPENAI_MODEL` の接続先と API キーが要る。この呼び出しは手元のコーパスでは代えられず、API キーを持っていても同じ判定が返る保証はない。

固定できるのは分類器のバージョンまでで、モデルの応答は固定できない。この実験で取った判定は、生成の方針のバージョンを `v2-corrected` として持ち、そのバージョンの方針は `../../noun/votes/README.md` から引ける。一方、モデルは提供側が差し替えれば同じ入力でも答えが変わるので、この記録の一致率は、2 つのモデルが 2026-08-30 に返した応答に対する値である。

## 手順

実行したのは次のコマンドである。再現には venv と `~/.env` が要り、用例は添えていない。バッチの組み方は種で決まるため、同じ種なら同じバッチになる。

```
# バッチの組み方を変えて 2 回(1 回目の種 1001、2 回目の種 2002)
python chunk_effect.py --words ../../noun/inputs/jmdict-noun-headwords.txt \
    --out-dir . --model-key ANTHROPIC_MODEL

# 対照。バッチの組み方を固定して 2 回(どちらも種 1001)
python chunk_effect.py --words ../../noun/inputs/jmdict-noun-headwords.txt \
    --out-dir . --model-key ANTHROPIC_MODEL --same-chunking

# バッチの大きさを変えて掃引する
python chunk_effect.py --words ../../noun/inputs/jmdict-noun-headwords.txt \
    --out-dir . --model-key ANTHROPIC_MODEL --chunk 10 --label=-chunk10

# 食い違いを検出器が読む水準まで下ろして数える
python chunk_effect_report.py chunk-effect-*.json > chunk-effect-summary.txt
```

## 結果

中項目の集合が一致した語の割合は、バッチの組み方を変えたときと固定したときで次のように分かれた。

| 条件 | Haiku | luna |
|---|---|---|
| 同じバッチの組み方で 2 パス(対照) | 100.0% | 100.0% |
| バッチの組み方を変えて 2 パス | 65.0% | 75.9% |

対照は、判定が返った全語で一致した(Haiku 400 語、luna 399 語)。つまり、温度 0 の判定はバッチを固定すれば再現するので、食い違いはすべてバッチの中身に帰し、パスごとの揺れではない。

食い違いの深さは 3 段の指標で測った。

| 指標 | Haiku | luna |
|---|---|---|
| 中項目の集合の一致 | 65.0% | 75.9% |
| 部門の集合の一致 | 81.0% | 81.5% |
| 具体物の条件の一致 | 95.5% | 93.0% |

中項目の水準では 3 分の 1 が動くのに具体物の条件が保たれたのは、食い違いの大半が語義を 1 つ足すか落とすかの違いだからである。2 つのパスで中項目が 1 つも重ならなかった語は、Haiku で 26 件、luna で 36 件だった。

バッチを小さくしても食い違いは解消しなかった。Haiku で 1 バッチの語数を変えた結果は次のとおりである。

| 1 バッチの語数 | 20 | 10 | 4 |
|---|---|---|---|
| 中項目の集合の一致 | 65.0% | 64.5% | 70.8% |

費用はバッチの大きさに反比例して増えるので、4 語にすると 20 語の 5 倍を払って 70.8% にしかならない。バッチ内の位置による偏りもなく、位置ごとの語義の数の平均は 1.00 から 1.45 の幅に散り、前半と後半の差は 0.06 以内に収まった。頻度のタグを持つ 51 語の一致は 60.8% で、タグのない 349 語の 65.6% を下回った。

## 考察

第 1 に、1 パスの判定だけで作った表は、バッチの組み方という記録されない条件に依存する。同じ方針・同じモデル・同じ温度で作り直しても、バッチの組み方が違えば中項目の 3 分の 1 が変わる。

第 2 に、それでも `concrete-noun-misfit` への影響は小さく収まる。動くのは語義の数で、具体物の条件はほとんど動かない。表を差し替えるかどうかの判断は、この揺れでは変わらない。

第 3 に、揺れる語は、モデルがその語の語義の数を決めかねている語である。だから揺れ自体が、判定が割れた語を指す手がかりになる。

## 本番の生成への反映

この結果を受けて、本番の生成では日常的に使われる語にパスを重ね、2 パス以上が挙げた中項目だけを採る。母集団の作り方と確定の規則は `../../noun/votes/README.md` にあり、判定を保存する JSONL のフィールドの定義は `../../pipeline/votes.py` の冒頭にある。バッチの識別子、バッチ内の位置、パスの種を行に残すのは、バッチの影響を後から統計で検査できるようにするためである。
