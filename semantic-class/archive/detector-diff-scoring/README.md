# 意味分類表を引く残り 2 検出器の差分の判定

意味分類表を引く検出器のうち、`role-conflict` と `standalone-calque` の 2 つは、表を差し替えるかどうかの判断材料にならない。意味分類表とは、名詞ごとに意味の区分を並べた表であり、この 2 つのほかに `concrete-noun-misfit` が引く。2026-08-30 に、表を分類語彙表由来のものから Haiku v2 表へ差し替え、前後の設定で 3 つのコーパスへ lint を掛けて指摘を突き合わせた。`role-conflict` は指摘が 66 件のまま動かず、入れ替わったのは 4 件だけだった。`standalone-calque` は 485 件から 138 件へ 71% 減ったが、消えた側と増えた側から 30 件ずつ抜いて当否を判定したところ、直すべき文を指した指摘は 1 件も無かった。

2 つの検出器は、意味分類表の引き方が違う。`standalone-calque` が探すのは、1〜2 字の漢語が抽象的な語の多い段落に単独で立つ箇所である。その漢語が具体と抽象の両方の分類を持ち、第 2 義以降の英訳が計算機分野の語と一致すると報告する。表が無ければ何も出せない。`role-conflict` は、両立しない役割が同じ語に立つ箇所を報告し、その役割の判定で主語の語がどんな種類のものかを表から引く。

当否は LLM が判定した結果で、今回の判定に人手の確認は入っていない。判定の基準は `../../eval/methodology.md` にあり、定着した用法と専門用語への指摘を誤検出、読み手が引っかかる比喩・擬人化・直訳への指摘を妥当とした。誤検出とは、直すべきでない文への指摘をいう。理由付けが不正確でも、直すべき箇所を指した指摘は誤検出に数えない。

この測定が出すのは適合率だけである。適合率とは、検出器が出した指摘のうち妥当だったものの割合をいう。指摘しなかった候補を見ていないので、見逃した指摘である偽陰性も、指摘せずに済ませた正しい箇所である真陰性も数えていない。したがって、指摘すべきだったもののうち実際に指摘した割合である再現率は出せない。

## 入力データ

差し替えの前後で使った表・コーパス・設定は次のとおりである。

| データ | パス | バージョン・日付 | 件数 |
|---|---|---|---|
| 分類語彙表由来の意味分類表 | akunuki の `.aku/reference/semantic-class-table.tsv`(外部) | 2026-08-30 時点の akunuki の同梱物 | 96,557 行 |
| Haiku v2 表 | `../haiku-contract-iteration/haiku-v2-semantic-class-table.tsv` | 2026-08-30 | 7,693 行 |
| 対訳表 | akunuki の `.aku/reference/gloss-table.tsv`(外部) | JMdict created 2026-08-24 | 48,462 行 |
| 評価コーパス | 外部 | — | Markdown 300 ファイル |
| docs A | 外部 | — | Markdown 42 ファイル |
| docs B | 外部 | — | Markdown 9 ファイル |
| 分類語彙表由来の表を指す設定 | `configs/cfg-old-v4.toml` | 2026-08-30 | — |
| Haiku v2 表を指す設定 | `configs/cfg-haiku2-v4.toml` | 2026-08-30 | — |

## 前提条件

この比較で変えたのは意味分類表だけである。同梱した `cfg-old-v4.toml` と `cfg-haiku2-v4.toml` は実験時の設定を凍結したもので、1 バイトも違わない。どちらも `abstract_ratio` が 0.85、`standalone-calque` が `enabled = true`、`role-conflict` の `copula_division` が `true` である。このうち `abstract_ratio` は、今回の 2 検出器には効かない。2 つの設定は同じ相対パス `reference/semantic-class-table.tsv` を書いており、その先が指す表だけを入れ替えた。

`reference/` は設定ファイルのパスからの相対で解決され、その symlink はリポジトリに入っていない。したがって、同梱の 2 つの設定をそのまま使っても表の差は再現できない。分類語彙表由来の表は akunuki の同梱物から、Haiku v2 表は `../haiku-contract-iteration/haiku-v2-semantic-class-table.tsv` から、`reference/` を自分で組む必要がある。

指摘を出した akunuki のバイナリのバージョンは記録がない。検出器の実装が変われば件数も変わるため、66 件と 485 件は 2026-08-30 の測定に使ったバイナリに対する値である。

3 つのコーパスはリポジトリに入っていない。手元の別の Markdown へ差し替えれば手順は動くが、件数はこの記録と一致しない。差し替えても確かめられるのは、表を替えると `standalone-calque` の指摘が入れ替わり、`role-conflict` はほとんど動かないという形のほうである。抜いた標本の本文は置いていないが、当否は `verdicts_v4.py` にあるので、判定の読み直しはコーパスが無くてもできる。

## 手順

既定のままでは測れない項目が 2 つあるため、両方の設定で同じように変えた。`standalone-calque` は既定で無効なので有効にした。`role-conflict` の `copula_division` も既定で無効なので有効にし、コピュラの判定が引く表も測る範囲に入れた。コーパスは 3 つとも読み取り専用で、`aku fix` は実行していない。実行したのは次のコマンドである。

```
# 2 つの設定で 3 コーパスへ lint を掛ける(閾値はこの 2 検出器に効かない)
bash lint_v4.sh cfg-old-v4    v4old
bash lint_v4.sh cfg-haiku2-v4 v4haiku

# 指摘を突き合わせる。鍵はパスと行と桁と語である
python diff_v4.py > diff-v4.txt

# 差分が大きい側から種 694 で 30 件ずつ抜く
python sample_diff_v4.py standalone-calque lost   > sample-v4-calque-lost.txt
python sample_diff_v4.py standalone-calque gained > sample-v4-calque-gained.txt
```

指摘の文面には分類番号が埋まり、表ごとに変わる。文面を鍵に入れると、同じ箇所が消えた側と増えた側の両方に並ぶので、鍵からは文面を外した。

## 結果

2 つの表での指摘の件数と、差分から抜いた標本の適合率は次のとおりである。

| 指標 | `role-conflict` | `standalone-calque` |
|---|---|---|
| 分類語彙表由来での指摘 | 66 件 | 485 件 |
| Haiku v2 表での指摘 | 66 件 | 138 件 |
| 両方が出す指摘 | 64 件 | 74 件 |
| 消えた指摘 | 2 件 | 411 件 |
| 増えた指摘 | 2 件 | 64 件 |
| 消えた指摘の適合率 | 2/2 | 0/30 |
| 増えた指摘の適合率 | 2/2 | 0/30 |

`role-conflict` はほとんど動かなかった。動いた 4 件は、消えた 2 件も増えた 2 件も妥当な指摘だった。差し替えはこの検出器について中立である。

`standalone-calque` は指摘が 71% 減った。ただし標本の妥当は、減る前も減った後も 0 件だった。表を替えても誤検出の機構は変わらず、指摘の出る場所が入れ替わって総数が減っただけである。

## `role-conflict`

`role-conflict` の意味分類表への依存は任意で、主語の部門とコピュラの判定に使う。コーパスごとの件数は、2 つの表で完全に一致した。

| コーパス | 分類語彙表由来 | Haiku v2 表 |
|---|---|---|
| 評価コーパス 300 ファイル | 8 | 8 |
| docs A | 35 | 35 |
| docs B | 23 | 23 |
| 合計 | 66 | 66 |

両方が出した指摘は 64 件で、消えたのが 2 件、増えたのが 2 件だった。述語ごとの内訳も 2 つの表で一致した。多い順に `黙る` が 19 件、`捨てる` が 8 件、`落とす` が 6 件、`消える` が 3 件だった。コピュラの判定による指摘は、どちらの表でも 2 件である。両方が出した 64 件のうち 17 件では、指摘の文面に載る分類番号だけが変わった。

差分が 4 件しかないので、全件の当否を判定した。消えた 2 件はどちらも妥当で、主語は `数量` と `片側` である。どちらも `黙る` を物の主語に立てた擬人化であり、`role-conflict` の価値を示す例として人手で確かめた型と同じである。Haiku v2 表ではこの 2 語が部門 2 の語義を得るため、語の側で除外された。

増えた 2 件もどちらも妥当で、主語は `実行時間` と `バージョン` である。`実行時間` の側では、`黙って落とさない` の動作主が書き手の作る仕組みであって実行時間ではない。`バージョン` の側では、`黙って崩れる` の主語が `前提` であり、同じ行の `前提` への指摘と重複する。どちらも係り先の取り違えだが、指摘が直すべき箇所を指しているので誤検出には数えない。

## `standalone-calque`

`standalone-calque` の意味分類表への依存は必須で、表が無ければ何も出ない。既定では無効な検出器である。コーパスごとの件数は、表を替えるとどれも減った。

| コーパス | 分類語彙表由来 | Haiku v2 表 |
|---|---|---|
| 評価コーパス 300 ファイル | 285 | 57 |
| docs A | 130 | 54 |
| docs B | 70 | 27 |
| 合計 | 485 | 138 |

両方が出した指摘は 74 件で、消えたのが 411 件、増えたのが 64 件だった。指摘に出た語の種類は、分類語彙表由来の表が 39、Haiku v2 表が 19 である。差分が大きいので、消えた側と増えた側から種 694 で 30 件ずつ抜いて当否を判定した。妥当はどちらの側も 0 件だった。

消えた側で多かったのは、`日` が 106 件、`側` が 69 件、`組織` が 59 件、`種` が 34 件である。この検出器は、語の第 2 義以降の英訳が計算機分野の語の英訳と重なることを手がかりに、英語を写した疑いを報告する。ところが標本の `日` は「2026 年 6 月 24 日」の日付で、英訳の case が計算機分野の `ＣＡＳＥ` と重なるだけだった。英語を写した跡はない。残る 3 語も同じで、`側` は「OSS 側」「読む側」の立場、`組織` は「約 100 組織」の団体、`種` は「51 種」の類別を指す。

増えた側で多かったのは、`履歴` が 17 件、`画面` が 13 件、`台帳` が 10 件、`声` が 9 件である。誤検出の型は消えた側とまったく同じだった。`履歴` は「git 履歴」、`画面` は「画面に出る文言」、`台帳` は記録の一覧、`声` は「問題視する声」を指す。英訳が log、image、script、view と重なるのは対訳表の中の偶然であり、書き手が英語を写した跡ではない。

つまり表を替えても、誤検出の機構は変わらない。変わるのは段落の部門の統計で、指摘の出る場所が入れ替わり、総数が減るだけである。

## 差し替えによる指摘の増減

失うものは、`role-conflict` の妥当な指摘 2 件である。代わりに同じ検出器で妥当な指摘を 2 件得るため、差し引きは変わらない。`数量` と `片側` の 2 件はどちらも `黙る` の擬人化で、この検出器の狙いに正面から当たる型である。

得るものは、`standalone-calque` の指摘が 485 件から 138 件へ 71% 減ることである。ただし標本では減る前も減った後も妥当が 0 件なので、減るのは誤検出の量だけである。

変わらないものは、`role-conflict` の総数 66 件と、述語ごとの内訳と、両方が出す 64 件である。この検出器の指摘は、ほぼすべてが表の選択で動かない。

## 表の差し替えの可否

`role-conflict` では、差し替えは中立である。妥当な指摘を 2 件落として 2 件得るため、差し引きは変わらない。66 件のうち 4 件しか動かないのは、表の質の差というより、判定の境界の揺れに近い。`黙る` を物の主語に立てる型は 19 件あり、その大半を両方の表が出す。したがって、この検出器を理由に分類語彙表由来の表を保つ根拠はない。

`standalone-calque` では、どちらの表を選んでも、この検出器を有効にしてよいかは決まらない。標本 60 件で妥当が 1 件も出なかったため、どちらの表でも誤検出しか出ていない見込みが高い。config のコメントによれば、既定で無効なのは実測の根拠を確かめられていないためであり、今回の 60 件はその根拠を得る材料になる。手がかりは対訳表の第 2 義以降の英訳の重なりで、`日` と case、`履歴` と log のように、日本語の側に何の異常もない語を大量に拾う。

この 2 検出器からは、`concrete-noun-misfit` と同じ形が読み取れる。表を替えても指摘の質は動かず、動くのは量だけである。だから差し替えの可否は、この 2 検出器では決められない。
