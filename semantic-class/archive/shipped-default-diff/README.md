# 出荷された既定どうしの比較

akunuki の意味分類表を差し替える変更の前後で、利用者が何も設定しなければ受け取る検出の結果がどう変わるかを 2026-08-30 に測った。表と閾値が同時に変わるため、部分ごとには測らず、出荷された既定どうしを突き合わせた。差し替え前の既定は分類語彙表由来の表と `abstract_ratio` 0.7、差し替え後は `semantic-class-v1` と 0.85 である。

`concrete-noun-misfit` は、抽象的な内容の段落に具体物の名詞が立つ箇所を指摘する。この検出器の指摘は、4 つの対象の合計で 1,364 件から 1,071 件へ 21% 減った。ただし前後の両方に出る指摘は 240 件しかなく、8 割は別の指摘に入れ替わっていた。入れ替わりの向きは狙いどおりで、抜いた 30 件のうち妥当な指摘は 1 件から 3 件へ増え、全体の概算でも 45 件から 107 件へ増えた。主語と述語の組が合わない箇所を指摘する `role-conflict` は、69 件から 71 件でほとんど動かなかった。

| 差し替え後の表 | `../../noun/semantic-class-table.tsv` | `semantic-class-v1` | 169,238 語 |

| 設定 `cfg-after.toml` | `configs/` に同梱 | 実験時のスナップショット | — |

## 前提条件

同梱の `configs/cfg-before.toml` と `configs/cfg-after.toml` で違うのは `abstract_ratio` の 1 行だけで、前者が 0.7、後者が 0.85 である。ほかのキーはすべて一致する。どちらも意味分類表を `reference/semantic-class-table.tsv` という相対パスで指すので、表の違いは設定ファイルにはなく、設定と並べて置いた `reference/` の中身にあった。差し替えの前後で既定が変わったのは表と `abstract_ratio` の 2 つだけであり、`git diff` で確かめた。

指摘を出したバイナリは、akunuki の `1cda27da` を `cargo build --release` で組んだものである。前後の実行で同じバイナリを使い、替えたのは設定だけである。

リポジトリに入っていないのは、4 つの対象のうち 3 つのコーパスと、差し替え後の表を置いた `reference/` である。残る 1 つの akunuki 自身の文書は公開のリポジトリにあるので、`1cda27da` を出せばそのまま同じ入力になり、差し替え前の表も `git show` の 1 行で履歴から取り出せる。コーパス 3 つを手元の Markdown へ差し替えれば lint 自体は動くが、その件数は結果の節の値と比べられない。再現の手順に API の呼び出しは含まれない。

## 当否の判定と測定の範囲

指摘の当否は LLM が自動で判定したもので、人手の確認を経ていない。判定の基準は `../finding-verdicts/verdicts_v2.py` と同じである。定着した語義と専門用語への指摘は誤検出、読み手が引っかかる未定着の転用や直訳への指摘は妥当とした。

この測定が出せるのは適合率だけである。適合率は、検出器が出した指摘のうち妥当だったものの割合であり、分母は出した指摘の件数である。検出器が指摘しなかった候補を見ていないため、指摘すべきなのに指摘しなかった偽陰性と、指摘すべきでなく指摘もしなかった真陰性は測っていない。したがって、指摘すべきだったもののうち実際に指摘したものの割合である再現率も出せない。評価の枠組みは `../../eval/methodology.md` にある。

## 手順

akunuki のソースと設定には触れず、次のコマンドでビルドと lint だけを実行した。コーパスは読み取り専用で扱い、`aku fix` は掛けていない。

```
# 差し替え前の表を履歴から取り出す
git show 411e4817^:.aku/reference/semantic-class-table.tsv > old-semantic-class-table.tsv

# 4 つの対象へ、前後の設定で lint を掛ける
bash run.sh

# 指摘を突き合わせる。鍵はパスと行と桁と語である
python diff.py concrete-noun-misfit
python diff.py role-conflict

# 前後それぞれから種 694 で 30 件を抜く
python sample.py before
python sample.py after
```

## 結果

意味分類表を引く検出器のうち、既定で有効なのは `concrete-noun-misfit` と `role-conflict` の 2 つである。`standalone-calque` も表を引くが、既定で無効なので対象から外した。対象ごとの件数は次のとおりだった。

| 対象 | 検出器 | 前 | 後 | 差 |
|---|---|---|---|---|
| 評価コーパス | `concrete-noun-misfit` | 967 | 657 | -310 |
| docs A | `concrete-noun-misfit` | 186 | 200 | +14 |
| docs B | `concrete-noun-misfit` | 161 | 154 | -7 |
| akunuki 自身 | `concrete-noun-misfit` | 50 | 60 | +10 |
| 合計 | `concrete-noun-misfit` | 1,364 | 1,071 | -293 |
| 合計 | `role-conflict` | 69 | 71 | +2 |

減ったのは評価コーパスだけで、残る 3 つは増えた。総数が減ったように見えるのは、評価コーパスが分母の 7 割を占めるためである。

## 入れ替わりの規模

`concrete-noun-misfit` で前後の両方に出る指摘は 240 件しかない。消えたのが 1,124 件、増えたのが 831 件である。表と閾値を同時に替えたため、指摘の 8 割が別物になった。

`role-conflict` は消えた指摘が 0 件で、増えたのが 2 件だけである。述語ごとの内訳も動かない。この検出器は表の差し替えに反応しない。

## 消えた指摘の型

多い順に `標的` 101 件、`パッチ` 72 件、`背景` 63 件である。以下、`キー` 50 件、`鍵` 49 件、`バイパス` 33 件と続く。定着した専門用語への誤検出として名指しされてきた語が、そのまま上位を占める。攻撃の対象を指す `標的`、修正版を指す `パッチ`、暗号鍵を指す `鍵` のように、いずれも現代の技術文書で普通に読める使い方である。新しい表がこれらの語に抽象の語義を与えるため、語の側で除外される。

## 増えた指摘の型

多い順に `パッケージ` 31 件、`表` 30 件、`オープンソース` 22 件、`ブラウザ` 22 件、`モジュール` 21 件である。カタカナで書く計算機の語が上位に来る点は、生成した表の既知の弱点のとおりである。`パッケージ` も `オープンソース` も、その分野で普通に使う語である。

一方、狙いに当たる指摘も新しく出た。`透かし` は watermark の直訳で、取得の進み具合を示す目印を指す語としては日本語に定着していない。

## 適合率の推定

前後それぞれの指摘から種 694 で 30 件を抜き、LLM が 1 件ずつ当否を判定した。すでに判定した語はその結果を引き継ぎ、新しく出た語だけを判定した。前後の指標は次のとおりで、信頼区間は Wilson の方法で求めた。

| 指標 | 前 | 後 |
|---|---|---|
| 指摘の総数 | 1,364 | 1,071 |
| 標本の適合率 | 1/30 = 3.3% | 3/30 = 10.0% |
| 95% 信頼区間 | 0.6%〜16.7% | 3.5%〜25.6% |
| 妥当の概算 | 45 件 | 107 件 |

前で妥当としたのは `レバー` の 1 件である。英語の lever をそのまま写した語で、日本語では手段か打ち手と書く。後で妥当としたのは `バケット`・`窓`・`透かし` の 3 件で、順に bucket・window・watermark の直訳である。

前後の信頼区間が重なるため、適合率の差は統計としては確定しない。ただし絶対数で見ると、妥当の概算は 45 件から 107 件へ 2 倍を超えて増え、指摘の総数から妥当の概算を引いた誤検出の概算は 1,319 件から 964 件へ 27% 減った。誤検出を減らしながら、当たりを増やした形である。

## akunuki 自身の文書の変化

akunuki のリポジトリに既定で `aku lint` を掛けたとき、利用者が最初に受け取るのは重大度ごとの件数である。前後の件数は次のとおりだった。

| 重大度 | 前 | 後 | 差 |
|---|---|---|---|
| warn | 98 | 98 | +0 |
| info | 882 | 892 | +10 |

warn は前後とも 98 件で、増えた 10 件はすべて info の `concrete-noun-misfit` だった。ほかの 27 の規則の件数は前後で同じだった。warn が動かないので、終了コードの振る舞いも変わらない。

`--show-info` を渡すと、warn と info の合計が見える。この合計は 980 件から 990 件へ 1.0% 増えた。表を差し替えても、利用者が最初に受け取る件数はほとんど変わらない。

## 所見

第 1 に、総数は 21% しか減らないのに、入れ替わりは 8 割に及ぶ。件数だけを見ると小さな変更に見えるが、指摘の中身はほぼ別物である。総数の減りだけからは、この入れ替わりの規模はわからない。

第 2 に、入れ替わりの向きは狙いどおりである。消える側は定着した専門用語に集中し、増える側にはカタカナの計算機の語という既知の弱点と、`透かし` のような狙いに当たる指摘の両方が混じる。標本では後者の比率が上がった。

第 3 に、`role-conflict` はこの差し替えでは動かない。表を替える判断の材料にこの検出器は使えず、これは `../detector-diff-scoring/` の記録と同じ結論である。

第 4 に、`concrete-noun-misfit` の指摘の適合率はまだ 1 割である。この値は、定着した語義への指摘を誤検出と数える基準によるものであり、既定で info のこの 1 検出器だけに掛かる。akunuki 全体の適合率ではない。残る 9 割は誤検出のままで、その多くはカタカナで書く計算機の語に集中する。
