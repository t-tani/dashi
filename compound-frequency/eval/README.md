# 正解つきの語の集合

複合語の頻度フィルタが語を正しく振り分けられるかは、答えのわかっている語で測る。その語の集合をこのフォルダに置き、`corpus-tool` の `judge --eval` に渡す。`judge` が語に付ける既存語・グレー・造語の候補・転用の候補の 4 つの名前は、`../design.md` の「判定の名前」が定める。

## 集合の一覧

答えのわかっている語は、正解の側と語の形と採り先で TSV に分けて置く。

| ファイル | 語数 | 中身 | 判定者 |
|---|---:|---|---|
| `coined.tsv` | 204 | akunuki の記録から採った語 | `maintainer` が中心 |
| `established.tsv` | 563 | 技術文書の取り置き 2 ソースに 2 回以上現れる既存語 | `claude-fable-5-1` |
| `established-security.tsv` | 347 | 日本語コーパスの取り置き 2 ソースに定着したセキュリティの既存語 | `claude-fable-5-1` |
| `coined-unknown.tsv` | 3 | 解析辞書にない 1 形態素で、記録から採った語 | `maintainer` |
| `established-unknown.tsv` | 269 | 解析辞書にない 1 形態素の既存語 | `claude-fable-5-1` |

1 語 1 行の TSV で、列は語と判定者と出典である。判定者はその語を正解のどちら側に置くかを決めた人かモデルで、出典の列にはその語の採り先が入る。この 2 列があるので、判定を後から見直せる。記録から採った語はこの 3 列の後ろに区分と区分の判定者の 2 列を持ち、区分の値は `造語` と `言い換え` と `意味の転用` の 3 つである。語ごとの区分と、そう決めた理由は `coined-review.md` にある。

`coined.tsv` と `established.tsv` と `established-security.tsv` には、分割単位 A で 2 形態素以上に割れる語だけが入っている。akunuki は 1 形態素の語を複合名詞の候補にしないため、その語でフィルタを引くこともない。`道具`・`資産`・`束` のように 1 語を別のものに当てた意味の転用は、この条件で落ちる。`judge --unknown-morphemes` は解析辞書にない 1 形態素も候補にして条件を変えるため、その選択のための語は `coined-unknown.tsv` と `established-unknown.tsv` に分かれている。

既存語の採り先は、評価用の成果物が頻度に入れないソースである。頻度を数えた本文と、その頻度で測る本文を分けるためである。除外の内容は `../design.md` の「正解集合の採り先の除外」にある。

## 指標の定義

判定の当たり方は、混同行列と 4 つの割合で測る。混同行列は、正解の区分を行、判定を列にして語数を並べた表である。再現率は、指摘すべきだった語のうち実際に指摘した語の割合を指し、誤検出率は、指摘してはいけない語のうち指摘した語の割合を指す。既存語なのに造語の候補と判定した語が偽陽性にあたる。

混同行列から次の割合を出す。

| 割合 | 定義 |
|---|---|
| 造語の再現率 | 区分が `造語` の語のうち、造語の候補と判定した割合 |
| 言い換えの誤検出率 | 区分が `言い換え` の語のうち、造語の候補と判定した割合 |
| 既存語の誤検出率(偽陽性率) | 既存語の例のうち、造語の候補と判定した割合 |
| グレー率 | 判定したすべての語のうち、グレーと判定した割合 |

再現率の母数は、区分が `造語` の 129 語である。`言い換え` と `意味の転用` は実在する用語なので、母数に含めない。既存語の誤検出率は、集合ごとに出す。

## 記録から採った語

`coined.tsv` の 204 語は、akunuki が語の使い方を記録した資料から採る。採り先ごとの語数と判定者は次のとおりである。パスは akunuki のリポジトリの根から書く。

| 採り先 | 語数 | 判定者 |
|---|---:|---|
| `.aku/dict/report/avoid/user.yaml` | 75 | `maintainer` |
| `docs/slop-inventory.yaml` | 64 | `maintainer` 58、`claude-fable-5-1` 6 |
| `.aku/dict/fix/wording/user.prh.yml` | 51 | `maintainer` |
| akunuki の issue | 8 | `claude-fable-5-1` |
| `seeds/dict-specs.yaml` | 6 | `maintainer` |

`avoid/user.yaml` は、セキュリティ記事のコーパスを校正して使わないと決めた語である。`fix/wording/user.prh.yml` は、同じ校正で直訳から定着語へ寄せた語で、`供給網`・`社会工学`・`赤チーム` がこれにあたる。`slop-inventory.yaml` の 6 語は、メンテナーではなくエージェントが確認した語で、確認したバージョンが記録に残っていないため、判定者の列には `claude-fable-5-1` が入っている。akunuki の issue の本文から採れるのは、`構造系`・`走査系` のように検出器のまとまりを `系` で名指す 8 語だけである。issue の本文は同じ辞書で校正するため、記録に残った語より外はほとんど残らない。

### 区分

204 語は、`造語` と `言い換え` と `意味の転用` のどれかに分かれる。区分ごとの意味と語数は次のとおりである。

| 区分 | 意味 | 語数 | 採り先の内訳 |
|---|---|---:|---|
| `造語` | 語そのものが存在しない語で、この仕組みが拾う対象 | 129 | `avoid/user.yaml` 74、`slop-inventory.yaml` 47、akunuki の issue 8 |
| `言い換え` | 実在する用語だが akunuki が別の表記を選んだ語で、拾ってはいけない | 56 | `fix/wording/user.prh.yml` 51、`seeds/dict-specs.yaml` 5 |
| `意味の転用` | 実在する用語を別の意味や曖昧な意味で使った語で、語の有無では拾えない | 19 | `slop-inventory.yaml` 17、`avoid/user.yaml` 1、`seeds/dict-specs.yaml` 1 |

区分は、語を採った記録が何を記録しているかで決める。`fix/wording/user.prh.yml` は実在する用語を選んだ表記へ寄せる記録なので、そこから採った 51 語は機械で `言い換え` にする。`seeds/dict-specs.yaml` から採った 5 語も `fix` の書き換えを定めた仕様なので、`言い換え` へ置く。残る 148 語は、`claude-fable-5-1` が `avoid/user.yaml` の hint と `slop-inventory.yaml` の referent と note を 1 語ずつ読んで、`造語` と `意味の転用` に分ける。

区分の判定者は 204 語とも `claude-fable-5-1` である。メンテナーが確かめた語は、区分の判定者を `maintainer` へ書き換える。

`意味の転用` の 19 語は、`樹形図`・`資格審査`・`ドリフト検出`・`未知語`・`供給源`・`未接続`・`未取得`・`配布先`・`配信元`・`観測点`・`共変動`・`代理指標`・`監視対象`・`状態機械`・`参照資料`・`二本立て`・`壁時計`・`推進役`・`不安全` である。

## 既存語の例

`established.tsv` の 563 語は、技術文書の `owasp-top10` から 92 語、`ts-survival` から 471 語を採る。採り方は機械の絞り込みで、平文から漢字とカタカナが 3 文字以上続く区間を切り出し、送り仮名で切れた断片を落とし、2 回以上現れる語を残す。残った語を既存語と決めた判定者は `claude-fable-5-1` である。記録から採った語と重なる `供給網`・`サービス妨害`・`破壊的操作` は、記録の側を採ってここから外す。

`型注釈`・`余剰プロパティチェック`・`型ガード関数` のように、解析辞書に見出しがないのに技術文書で定着した語が入る。造語と紛らわしい語をここへ含めるのは、既存語の誤検出率がその紛らわしさで決まるためである。

## セキュリティの既存語の例

`established-security.tsv` の 347 語は、日本語コーパスの `jpccert-eyes` から 320 語、`ipa-websec` から 27 語を採る。出典の列は、その語が現れた最初の文書のソース名とファイル名である。

3 段に分けて採る。第一に、2 ソースの平文だけを `count --corpus-dir` に通し、2 文書以上に現れる複合語のキー 2,811 件を候補にする。第二に、`established.tsv` と `coined.tsv` にある語と、1 文字の語を候補から外す。第三に、`claude-fable-5-1` が残る 2,736 語を 1 語ずつ読み、分野に定着した語だけを残す。

第一段の候補は、次のコマンドで数える。

```
cd compound-frequency/corpus-tool
cargo run --release -- count --corpus-dir <日本語コーパス> --out-dir ../counts-security \
    --exclude board-of-audit,digital-guidelines,digital-procurement,egov-law-api,ipa-exam,ipa-procurement,jawiki,jpccert,jvn-ipedia,meti-dx,mext-joho2-kyoin,mext-johoshi-kyoin,mic-whitepaper-r06,mic-whitepaper-r07,nco-manual,nco-standards,nicter-reports,ppc-guidelines,raw,toshin-tsushin
```

落とす候補は 4 通りである。`型攻撃` と `性対策` と `名パラメータ` は、区間の切り出しが送り仮名や助詞で切れた断片にあたる。`JPCERTコーディネーションセンター公式ブログ` は文書ごとに繰り返される定型の見出しで、`文京区` と `本駒込二丁目` は差出人の住所である。`御確認` と `御知らせ` は表層形が本文に現れない正規化形で、この形は残した語の本文への完全一致で落とす。

残した語には `攻撃シナリオ` と `送信元IPアドレス` のような修飾の連なりも入る。akunuki はこの形も複合名詞の候補にするため、既存語の例から外すと、誤検出率の母数が候補の実際の形と食い違う。

## 解析辞書にない 1 形態素の集合

`coined-unknown.tsv` の 3 語は、`クレデンシャル` と `デニリスト` と `ファネル` である。akunuki の 4 つの記録からカタカナと英字だけの語を集め、そのうち `count` が解析辞書にない 1 形態素として数える語を採る。集めた記録は `docs/slop-inventory.yaml` と `.aku/dict/report/avoid/user.yaml` と `.aku/dict/fix/wording/user.prh.yml` と `seeds/dict-specs.yaml` である。`クレデンシャル` と `デニリスト` は書き換えの記録から採った語なので `言い換え`、`ファネル` はマーケティングの語をほかのものに当てた例なので `意味の転用` にあたる。3 語のどれも `造語` には入らない。

`established-unknown.tsv` の 269 語は、`owasp-top10` と `ts-survival` の平文を `count` に通し、`--unknown-morphemes` で新たにキーになる 509 件を候補にして採る。平文に 2 回以上現れる語を残し、1 文字の語と `inforeact` と `クレデンシャル` を外す。1 文字の語は箇条書きの記号と型変数で、`inforeact` は `:::info` の指示子が次の語につながった断片、`クレデンシャル` は記録から採った語にある語である。`typescript`・`eslint`・`ジェネリクス`・`ミュータブル` のように、分野に定着したのに解析辞書の見出しにない語がここに入る。

広げた集合は、元の集合と足す集合を連ねて作る。記録から採った語は 207 語(`造語` 129 語、`言い換え` 58 語、`意味の転用` 20 語)、既存語の例は 832 語になる。連ねたファイルは追跡していない。

2 つの集合は `cat` で連ねる。

```
cd compound-frequency/eval
cat coined.tsv coined-unknown.tsv > coined-all.tsv
cat established.tsv established-unknown.tsv > established-all.tsv
```

## 判定の結果

評価用の成果物を既定の引数の `judge` に掛け、記録から採った語 204 語と既存語の例 563 語とセキュリティの既存語の例 347 語を 2026-09-08 に判定した。掛けた成果物は、配布用と同じ入力から正解集合の採り先を除いて組んだものである。入力の来歴と版は `../manifest.json` が持つ。

判定に使ったコマンドは次のとおりである。

```
cd compound-frequency/corpus-tool
cargo run --release -- judge --artifacts-dir ../variants/evaluation --eval ../eval/coined.tsv \
    ../eval/established.tsv ../eval/established-security.tsv
```

正解の区分ごとの判定の内訳は次のとおりである。

| 正解の区分 | 語数 | 既存語 | グレー | 造語の候補 |
|---|---:|---:|---:|---:|
| `造語` | 129 | 3 | 13 | 113 |
| `言い換え` | 56 | 15 | 7 | 34 |
| `意味の転用` | 19 | 16 | 2 | 1 |
| 既存語の例 | 563 | 405 | 47 | 111 |
| セキュリティの既存語の例 | 347 | 328 | 12 | 7 |

割合にすると次の値になった。

| 割合 | 値 |
|---|---|
| 造語の再現率 | 113/129(87.6%) |
| 言い換えの誤検出率 | 34/56(60.7%) |
| 既存語の例の誤検出率 | 111/563(19.7%) |
| セキュリティの既存語の例の誤検出率 | 7/347(2.0%) |
| グレー率 | 81/1114(7.3%) |

`造語` で既存語になるのは 3 語である。`停止点` と `構造系` は完全一致が高頻度を返し、`樹形図` は解析辞書の見出しに当たる。対の連結の検査を挟まないため、`未認証データ` と `脆弱性連鎖` のように部品をつないだ造語は既存語に倒れない。

既存語の例で造語の候補になる 111 語は、分野に定着したのにコーパスにも解析辞書の見出しにも記事名にもない語である。`余剰プロパティチェック` と `型ガード関数` のような TypeScript の専門用語が、その大半を占める。セキュリティの既存語の例では、誤検出は 347 語のうち 7 語にとどまる。この集合の語は JPCERT/CC と IPA の説明文に繰り返し現れるため、Wikipedia の記事にも解析辞書の見出しにもある語が多く含まれる。

`言い換え` の 56 語のうち、造語の候補になるのは 34 語である。この区分の語は akunuki が別の表記を選んだだけで、語の形は句を詰めた造語と変わらない。`盲目的XSS` と `脅威インテル` と `宙吊りレコード` がその形で、コーパスにも解析辞書の見出しにもない。

## 分野の検査を当てた結果

同じ評価用の成果物を、文書の分野を情報技術として `judge` に掛けた。分野の検査は完全一致で既存語と決まった語にだけ当たるため、造語の候補とグレーの語数は分野の検査を当てない結果と同じである。動くのは既存語の列だけで、`造語` で 1 語、`言い換え` で 4 語、`意味の転用` で 4 語、既存語の 2 集合で 13 語が転用の候補へ移る。

掛けたコマンドは次のとおりである。

```
cargo run --release -- judge --artifacts-dir ../variants/evaluation \
    --document-domain 情報技術 --eval ../eval/coined.tsv \
    ../eval/established.tsv ../eval/established-security.tsv
```

正解の区分ごとの判定の内訳は次のとおりである。

| 正解の区分 | 語数 | 既存語 | グレー | 転用の候補 | 造語の候補 |
|---|---:|---:|---:|---:|---:|
| `造語` | 129 | 2 | 13 | 1 | 113 |
| `言い換え` | 56 | 11 | 7 | 4 | 34 |
| `意味の転用` | 19 | 12 | 2 | 4 | 1 |
| 既存語の例 | 563 | 395 | 47 | 10 | 111 |
| セキュリティの既存語の例 | 347 | 325 | 12 | 3 | 7 |

`意味の転用` の 19 語のうち、転用の候補になるのは 4 語である。

| 語 | 分野 |
|---|---|
| `未知語` | `その他の理工` |
| `共変動` | `その他の理工` |
| `参照資料` | `その他の理工・文化・地理・社会` |
| `推進役` | `その他の理工・文化・地理・社会` |

残る 15 語のうち 12 語は既存語のままである。9 語は 5 つ以上の分野で下限に届くため、一般で登録される。`樹形図`・`資格審査`・`供給源`・`未接続`・`未取得`・`配信元`・`観測点`・`監視対象`・`不安全` がこれにあたる。残る 3 語の `配布先` と `状態機械` と `壁時計` は、情報技術の記事にも下限以上に現れるため、情報技術で登録される。`ドリフト検出` と `代理指標` は、完全一致がバケット 1 を返してグレーになるため、分野の検査に届かない。`二本立て` は複合語の区間が数詞で切れるため、完全一致で当たらず造語の候補になる。

`造語` では `停止点` が、`言い換え` では `青チーム` と `逆解析` と `学習資源` と `自己拡散` が転用の候補になる。`停止点` は語の有無では既存語に倒れていた語で、分野の検査が別の名前を与える。残る 4 語は akunuki が表記を選んだだけの語なので、誤検出として読む。

既存語の 2 集合で転用の候補になるのは 13 語である。既存語の例の 10 語は `ユーティリティ型`・`トップ型`・`上位型`・`心理的負担`・`スター数`・`構造的型システム`・`執筆時`・`単集合`・`新ページ`・`執筆プロセス` で、セキュリティの既存語の例の 3 語は `インシデント調査`・`事案対応`・`根本的解決` である。

## 判定の限界

記録の意味は、語の有無と食い違うことがある。`停止点` と `構造系` は記録が直訳と造語として扱う語だが、どちらも Wikipedia の本文に 10 回以上現れる。語の有無で判定する仕組みはこの 2 語を既存語と読むため、`造語` に置いても再現率の分子には入らない。

`意味の転用` の語は語の有無では拾えず、分野の検査でも 19 語のうち 4 語しか拾えない。`言い換え` の語は実在する用語だが、形は句を詰めた造語と変わらないため、6 割が造語の候補になる。この 2 つの区分は、この仕組みの外側を示す行として混同行列に残している。
