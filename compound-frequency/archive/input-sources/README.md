# 複合語の頻度フィルタに入力を足した前後

複合語の頻度フィルタは、複合語が世の中でどれだけ使われているかを引く表である。この表を組む入力に、解析辞書の見出しと日本語の技術文書と日本語コーパスを 1 つずつ足し、正解つきの語での当たり方がどう動くかを測った。

いちばん効いたのは技術文書だった。実在する既存語 563 語のうち造語の候補へ誤って倒れる語は 134 語から 96 語へ減り、LLM が作った造語 129 語のうち拾える語は 108 語から 107 語へ 1 語だけ落ちた。日本語コーパスの法令はフィルタのキーを 77,786 件しか増やさず、正解つきの語で判定が動いたのも 1 語だけだったので、文語体の法令は外した。

測定に使った成果物は 2026-09-08 の既定で組んだものであり、配布用の成果物とは次の 4 つの点で既定が違う。当たり方の数も、そのぶん配布用の成果物とは違う。配布用の成果物の当たり方は `../../eval/README.md` にある。

| 選択 | 2026-09-08 の既定 | 同じ形にする引数 |
|---|---|---|
| 解析辞書にない 1 形態素 | 数えない | `count --count-known-only` |
| 固有名詞の見出し | 登録する | `dictionary-headwords --proper-nouns` |
| 部品の頻度表の下限 | 1 | `build --min-component-count 1` |
| 隣り合う対の連結の検査 | 挟む | `judge --concatenation established` |

## 入力データ

|---|---|---|---|
| Wikipedia のダンプ | `jawiki-20251229-cirrussearch-content.json.gz`(外部) | 2025-12-29 | 全記事 1,484,267 件 |
| 解析辞書の配布物 | SudachiDict の `small_lex`・`core_lex`・`notcore_lex`(外部) | 2026-07-23 | 名詞の見出し 2,274,679 件 |

| 日本語コーパス | `<日本語コーパス>`(外部) | — | 20 ソース |

| 照合する 3 群の語 | akunuki の `docs/slop-inventory.yaml` ほか(外部) | — | 60 語 |

## 前提条件

3 つの成果物は、`build` へ渡す回数のディレクトリの数だけが違う。固定したのは、ダンプと解析辞書のバージョンと、3 つの正解集合である。`count --count-known-only` と `build --min-component-count 1` と `judge --concatenation established` の引数も、どの成果物でも同じである。「解析辞書の見出しを入れた前後」の節では、同じ Wikipedia の回数に `dictionary-headwords` の出力を足すかどうかが差になる。法令の 2 つの成果物では、日本語コーパスから法令のソースを外すかどうかが差になる。

`corpus-tool` は akunuki の `aku_freq`・`aku_core`・`aku_morph` を、git の rev `a4d27caa92493d46cb60c29f975dca4d7526cc56` で固定して依存する。フィルタのキーは akunuki の分割単位 A で切るので、rev が違えばキーの数も当たり方も変わる。

`judge` に `--threshold` を渡していないので、部品の比の閾値は `corpus-tool` の既定の 1000 が効く。この値の根拠は `../../design.md` の「既定の根拠」にある。この閾値は既存語とグレーと造語の候補の名前を変えず、造語の候補の理由だけを分けるので、ここの割合は閾値に依らない。3 形態素以上の語の検査には、2026-09-08 の既定である `established` をコマンドで明示して渡した。

同じ数を出すには 4 つの入力が要り、そのうち 3 つはリポジトリにない。Wikipedia のダンプ `jawiki-20251229-cirrussearch-content.json.gz` は、古いバージョンが手に入らなくなる。解析辞書は 2026-07-23 の SudachiDict である。技術文書のソースごとの commit は `../../manifest.json` の `inputs.documents` にあるが、この記録は取得のたびに書き直されるので、同じ本文を取り直せるとは限らない。日本語コーパスはリポジトリに入っていないので、それを足した節は再現できない。正解つきの語の 3 つの TSV はリポジトリにある。

## 手順

`compound-frequency/corpus-tool` で実行した。`<ダンプ>` はダンプのディレクトリである。

```
# 2026-09-08 の既定で回数と見出しを作る
cargo run --release -- count --count-known-only \
    --dump <ダンプ>/jawiki-20251229-cirrussearch-content.json.gz --out-dir ../counts-known
cargo run --release -- count --count-known-only --text-dir ../corpus/text \
    --out-dir ../counts-docs-known
cargo run --release -- dictionary-headwords --proper-nouns \
    --lexicon-dir ../sudachidict --out-dir ../counts-known
cargo run --release -- count --count-known-only --corpus-dir <日本語コーパス> \
    --out-dir ../counts-corpus-nolaw \
    --exclude jawiki,raw,jpccert-eyes,ipa-websec,egov-law-api

# Wikipedia だけの成果物
cargo run --release -- build --counts-dir ../counts-known --min-component-count 1 \
    --out-dir ../variants/wiki

# 技術文書を足した成果物
cargo run --release -- build --counts-dir ../counts-known \
    --docs-counts-dir ../counts-docs-known --min-component-count 1 --out-dir ../variants/base

# 法令を外した日本語コーパスを足した成果物
cargo run --release -- build --counts-dir ../counts-known \
    --docs-counts-dir ../counts-docs-known --corpus-counts-dir ../counts-corpus-nolaw \
    --min-component-count 1 --out-dir ../variants/jacorpus-nolaw

# それぞれを 2026-09-08 の既定で判定する
cargo run --release -- judge --artifacts-dir ../variants/<成果物> --concatenation established \
    --eval ../eval/coined.tsv ../eval/established.tsv ../eval/established-security.tsv
```

法令を入れた日本語コーパスの成果物は、`count` が必ず外す文語体の法令も入れて組んだものである。リポジトリにある手順では同じ入力を作れないため、その成果物を組むコマンドはない。

### 技術文書を足した前後

混同行列は、行に正解の区分、列に成果物の判定を取り、語数を数えた表である。行の `造語` と `言い換え` と `意味の転用` は、`../../eval/coined.tsv` の `区分` の列が取る 3 つの値である。既存語の例とセキュリティの既存語の例は、`../../eval/established.tsv` と `../../eval/established-security.tsv` の語である。指摘すべきなのは `造語` の 129 語だけであり、`言い換え` と `意味の転用` は実在する用語なので、造語の候補に倒れれば誤検出になる。区分の決め方は `../../eval/README.md` の「区分」にある。

混同行列から出す割合は 4 つである。造語の再現率は、`造語` の 129 語のうち `judge` が造語の候補と判定した語の割合である。3 つの誤検出率は、`言い換え` の 56 語と既存語の例 563 語とセキュリティの既存語の例 347 語のそれぞれについて、同じ割合を出したものである。グレー率だけは分母が違い、判定したすべての語のうちグレーになった語の割合を指す。

| `言い換え` | 56 | 17 | 7 | 32 |

|---|---|---|
| 造語の再現率 | 108/129(83.7%) | 107/129(82.9%) |

技術文書を足すと、既存語の例の誤検出率は 6.7 ポイント下がり、造語の再現率は 0.8 ポイント下がった。造語で失ったのは `報告元` の 1 語である。この語は Wikipedia の 2 回に技術文書の 1 文書が足されて 3 回になり、バケット 1 のグレーへ動いた。

既存語の例のうち造語の候補になるのは、分野に定着したのにコーパスにも解析辞書の見出しにもない語である。`余剰プロパティチェック` と `型ガード関数` のような TypeScript の専門用語がその大半を占め、Wikipedia の全記事を数えてもこうした語は薄いままだった。技術文書を足すと、そのうち 38 語が造語の候補から外れた。`分割代入`・`リテラル型`・`スプレッド構文`・`型アサーション` は未登録から高頻度の既存語になり、`出力ディレクトリ` と `インデント幅` はグレーになった。38 語はどれも JavaScript と TypeScript と web 開発の専門用語であり、翻訳された公式文書がこれを埋める。

`造語` の語で既存語になるのは 9 語である。`停止点` と `構造系` は完全一致が高頻度を返し、残る `未認証データ`・`脆弱性連鎖`・`収集対象外` などの 7 語は隣り合う対がどちらも高頻度なので、対の検査が既存語の連結と読む。

`意味の転用` の 19 語では、どちらの成果物でも 16 語が既存語、2 語がグレーになる。造語の候補になるのは `二本立て` の 1 語だけである。複合語の区間は数詞で切れるので、`二` を含むこの語はキーにならない。

### 法令の有無

3 つの成果物の大きさと当たり方を並べる。

| 成果物 | キー数 | `freq_filter.bin` | `component_freq.fst` | 造語の再現率 | 既存語の例の誤検出率 | セキュリティの既存語の例の誤検出率 |
|---|---:|---:|---:|---|---|---|
| 基準 | 10,391,904 | 23,396,438 | 15,533,241 | 107/129(82.9%) | 96/563(17.1%) | 9/347(2.6%) |
| 法令なし | 10,416,181 | 23,461,974 | 15,548,843 | 105/129(81.4%) | 93/563(16.5%) | 7/347(2.0%) |
| 法令あり | 10,493,967 | 23,658,582 | 15,604,575 | 104/129(80.6%) | 93/563(16.5%) | 7/347(2.0%) |

法令を入れた成果物が数えた本文 544,725,258 バイトのうち、法令は 491,253,442 バイトと 9 割を占めた。このバイト数は、日本語コーパスの各ソースの `text/` に置かれた平文の大きさの和である。それでいて法令が増やしたキーは 77,786 件にとどまり、`freq_filter.bin` と `component_freq.fst` は合わせて 252,340 バイト大きくなっただけだった。法令以外の 53,471,816 バイトがキーを 24,277 件増やすので、バイトあたりで数えると法令は 3 分の 1 ほどしかキーを増やさない。法令の文が同じ言い回しを繰り返すためである。

この 77,786 件のキーに対して、正解集合の上で動いたのは `造語` の 1 語だけだった。この差を見て、文語体の法令を外す条件を `count` に入れた。口語体の法令は配布用の成果物に入れる。
