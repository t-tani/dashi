# 対の連結の検査を構成の分析に置き換えた前後

複合語の頻度フィルタは、3 形態素以上の語に、隣り合う 2 語の対がすべて高頻度なら既存語と決める検査を当てる。この検査は、`未認証データ` や `脆弱性連鎖` のように句を複合語へ圧縮した造語も既存語に倒す。そこで、語を左右 2 つの単位に分ける分割の点数で決める構成の分析に置き換え、当たり方の動きを測った。

置き換えると、圧縮された造語 5 語が既存語から造語の候補へ戻る。一方、分野に定着した既存語 11 語が逆に造語の候補へ落ちる。差し引きでは、造語 129 語のうち拾える語が 107 語から 108 語へ動き、実在する既存語 563 語のうち誤って倒す語は 96 語から 103 語へ動く。

3 形態素以上の語の検査の既定は、どちらの検査も挟まない `--concatenation off` である。この記録は、その既定が決まる前に対の検査と構成の分析を比べた測定である。

構成の分析の仕組みは `../../design.md` の「構成の分析」にある。成果物は 2026-09-08 時点の既定で組んだもので、その既定は、解析辞書にない 1 形態素を数えず、固有名詞の見出しを登録し、部品の頻度表の下限を 1 にする。基準の判定は、対の検査を挟む `judge --concatenation established` であり、構成の分析は `--concatenation composition` で選べる。点数を名前に分ける 2 つの閾値も、どこに置くかを確かめた。

## 入力データ

判定に使ったのは、成果物と 2 組の回数の TSV と 2 つの正解集合である。成果物と回数の TSV は、Wikipedia の全記事と技術文書から組んだ。表のパスは、この文書のディレクトリからの相対である。

| データ | パス | バージョン・日付 | 件数 |
|---|---|---|---|
| 成果物 | `../../variants/base`(外部) | ダンプ 2025-12-29・解析辞書 2026-07-23 | キー 10,391,904 件 |
| 回数の TSV | `../../counts-known`・`../../counts-docs-known`(外部) | ダンプ 2025-12-29・解析辞書 2026-07-23 | — |
| 造語の例 | `../../eval/coined.tsv` | — | 204 語 |
| 既存語の例 | `../../eval/established.tsv` | — | 563 語 |

## 前提条件

掃引の 14 行も基準との比較も、成果物 `../../variants/base` と 2 つの回数の TSV と 2 つの正解集合を固定し、`judge` の引数だけを変えた。掃引で変えたのは `--upper-threshold` と `--lower-threshold` の 2 つである。基準との比較で変えたのは `--concatenation` の値だけである。構成の分析は単位の回数を読むので、その行だけ `--counts-dir` と `--docs-counts-dir` を併せて渡した。

`corpus-tool` は akunuki の `aku_freq`・`aku_core`・`aku_morph` を、git の rev `a4d27caa92493d46cb60c29f975dca4d7526cc56` で固定して依存する。フィルタのキーは akunuki の分割単位 A で切るので、rev が違えばキーの数も当たり方も変わる。

基準との比較では 2 つの閾値を渡していないので、`corpus-tool` の閾値の既定である上 300・下 100 が効く。この値の根拠は `../../design.md` の「既定の根拠」にある。`--threshold` も渡していないので、部品の比の閾値は既定の 1000 が効く。

同じ数を出すには、まず成果物 `../../variants/base` を組み直す。組み方は `../filter-choices/README.md` にあり、Wikipedia のダンプ `jawiki-20251229-cirrussearch-content.json.gz`、2026-07-23 の SudachiDict、技術文書の 3 つが要る。ダンプは古い版が手に入らなくなる。技術文書のソースごとの commit は取得のたびに書き直される `../../corpus/raw/manifest.tsv` にしかなく、リポジトリにないので、同じ本文を取り直せるとは限らない。2 つの正解集合はリポジトリにある。

## 手順

`compound-frequency/corpus-tool` で実行した。

```
# 2 つの閾値を振る
cargo run --release -- judge --artifacts-dir ../variants/base --concatenation composition \
    --counts-dir ../counts-known --docs-counts-dir ../counts-docs-known \
    --upper-threshold <上> --lower-threshold <下> \
    --eval ../eval/coined.tsv ../eval/established.tsv

# 既定の閾値(上 300・下 100)で基準と比べる
cargo run --release -- judge --artifacts-dir ../variants/base --concatenation established \
    --eval ../eval/coined.tsv ../eval/established.tsv
cargo run --release -- judge --artifacts-dir ../variants/base --concatenation composition \
    --counts-dir ../counts-known --docs-counts-dir ../counts-docs-known \
    --eval ../eval/coined.tsv ../eval/established.tsv
```

解析辞書の見出しで回数の TSV にない単位は頻度がわからないので、その分割は点数に使わず、そのような分割を持つ語を別に数える。造語の例 204 語と既存語の例 563 語では、この形の語は 0 語である。見出しの `一世一代` は記事に 3 回未満しか現れないので、`一世一代処理` を判定するとこの数は 1 語になる。

## 結果

割合はどれも語数の比である。造語の再現率は、区分が `造語` の 129 語のうち造語の候補と判定した語の割合を指す。誤検出率も分子は造語の候補で、母数は `言い換え` の 56 語と既存語の例 563 語を使う。グレー率は、`意味の転用` の 19 語も含む 767 語を母数とし、グレーと判定した語を分子に取る。混同行列は、行に正解の区分、列に判定の名前を置き、語数を数えた表である。

2 つの閾値を同じ値にすると、グレーの帯が空になる。点数が名前を動かすのは帯の中だけなので、帯が空なら点数は何も決めない。割合は対の検査をやめた場合と同じで、再現率は 114/129 で 88.4%、既存語の誤検出率は 114/563 で 20.2%、グレー率は 67/767 で 8.7% である。

グレーの帯を広げるほど、再現率と誤検出率がそろって下がる。帯が空の組で造語の候補になる語のうち、上 300・下 100 の帯に入るのは `造語` の 6 語と既存語の例の 11 語である。母数で割ると `造語` の 4.7% に対して既存語の例は 2.0% で、帯には既存語より造語が多く入る。点数の中ほどには、疎さで落ちた既存語より圧縮された造語の方が多く入る。

構成の分析の閾値の既定である上 300・下 100 は、対の検査より造語の再現率が高い組のうち、既存語の誤検出率がいちばん低い組である。この組でも、再現率と誤検出率の差 65.4 ポイントは帯を空にした組の 68.2 ポイントに届かない。

対の検査を挟む基準の混同行列は次のとおりである。

|---|---:|---:|---:|---:|

2 つの混同行列から出した割合を並べる。

| 割合 | 基準 | 構成の分析 |
|---|---|---|
| 造語の再現率 | 107/129(82.9%) | 108/129(83.7%) |
| 言い換えの誤検出率 | 32/56(57.1%) | 34/56(60.7%) |
| 既存語の誤検出率 | 96/563(17.1%) | 103/563(18.3%) |
| グレー率 | 67/767(8.7%) | 85/767(11.1%) |

`意味の転用` の 19 語は、どちらの判定でも振り分けが変わらない。19 語のうち 18 語は 2 形態素なので、置き換えた検査に届かない。残る 3 形態素の `二本立て` は点数が下の閾値に届かないので、どちらの判定でも理由が `未登録` の造語の候補になる。

理由の内訳では、基準の `連結` 28 語が消え、`構成` 43 語が現れる。理由 `部品` は `造語` で 81 語から 62 語へ、`言い換え` で 21 語から 17 語へ、既存語の例で 43 語から 21 語へ減る。構成の分析は 3 形態素以上の語で部品の比の検査より先に名前を決めるので、その分だけ `部品` が減る。

### 3 形態素以上の語

置き換えたのは 3 形態素以上の語に当てる検査だけなので、2 形態素以下の 606 語は 1 語も動かない。動く 161 語だけを数えると、`意味の転用` の 19 語のうち 3 形態素以上は 1 語だけ入り、その 1 語は名前も理由も動かない。

| 正解の区分 | 判定 | 語数 | 既存語 | グレー | 造語の候補 |
|---|---|---:|---:|---:|---:|
| `造語` | 基準 | 35 | 7 | 1 | 27 |
| `造語` | 構成の分析 | 35 | 0 | 7 | 28 |
| `言い換え` | 基準 | 12 | 3 | 1 | 8 |
| `言い換え` | 構成の分析 | 12 | 0 | 2 | 10 |
| 既存語の例 | 基準 | 113 | 58 | 15 | 40 |
| 既存語の例 | 構成の分析 | 113 | 40 | 26 | 47 |

この範囲では、造語の再現率が 77.1% から 80.0% へ 2.9 ポイント上がり、既存語の誤検出率が 35.4% から 41.6% へ 6.2 ポイント上がる。構成の分析は既存語を返さないので、置き換えた側の既存語 40 語はどれも完全一致で決まった語である。

### 判定が変わった語

名前が動くのは 37 語で、`造語` が 11 語、`言い換え` が 4 語、既存語の例が 22 語である。`意味の転用` は 1 語も動かない。名前は同じで理由だけが変わる語は 42 語ある。

`造語` で拾えるようになるのは、既存語から造語の候補へ動く 5 語である。理由が連結から構成へ移るのは `収集対象外` と `脆弱性連鎖` と `意味論系` の 3 語で、連結から未登録へ移るのは `未認証データ` と `未認証コード` の 2 語である。`言い換え` でも `攻撃的セキュリティ` と `持続化機構` と `未認証者` が同じ向きに動き、こちらは誤検出が 3 語増える。

`造語` で再現率から落ちるのは、造語の候補からグレーへ動く 4 語である。`固定点判定` と `低複雑度` と `無害化不備` と `境界公開システム` がこれにあたる。`侵入後活動` と `中間者型` も帯に入るが、こちらは既存語からグレーへ動くので、造語の候補には届かないまま既存語と呼ばれなくなる。`言い換え` の `盲目的クロスサイトスクリプティング` も造語の候補からグレーへ動く。7 語とも点数が 100 以上 300 未満である。

既存語の例で誤検出に回るのは、既存語から造語の候補へ動く 11 語である。理由が連結から構成へ移るのは `平均発生率` と `合体演算子` と `推移的依存関係` と `脆弱性チェック` と `ステータス管理方法` の 5 語で、`構造的部分型` と `数値リテラル型` と `文字列結合演算子` と `名前的部分型` と `構造的部分型システム` と `日英対訳表` の 6 語は連結から未登録へ移る。11 語のうち 6 語は TypeScript の型と演算子の専門用語である。分野に定着した語をコーパスも解析辞書の見出しも持たないので、連結の検査を外すとそのまま造語の候補へ落ちる。

既存語の例では、ほかに 11 語がグレーへ動く。`オプション修飾子` と `自己終了タグ` と `インフラ構成管理` と `内部リンクブロック` は造語の候補からグレーへ動くので、誤検出を免れる。`制御フロー分析` と `網羅性チェック` と `文字列リテラル型` と `シングルスレッドモデル` と `値型変数` と `参照型変数` と `インライン型チェック` は既存語からグレーへ動くので、正しかった判定が薄れる。

### 句を圧縮した 3 語の点数

3 語とも、基準では隣り合う対がどちらも高頻度なので既存語の連結になり、構成の分析では造語の候補になる。区分は正解の側の区分で、`攻撃的セキュリティ` だけは拾ってはいけない `言い換え` である。点数は分割ごとの `min(f(左), f(右))` の最大値で、括弧の中はその点数を出した分割である。

| 語 | 区分 | 点数 | 基準 | 構成の分析 |
|---|---|---|---|---|
| `未認証データ` | `造語` | 31(`未` と `認証データ`) | 既存語(連結) | 造語の候補(未登録) |
| `脆弱性連鎖` | `造語` | 3,887(`脆弱性` と `連鎖`) | 既存語(連結) | 造語の候補(構成) |
| `攻撃的セキュリティ` | `言い換え` | 6,560(`攻撃的` と `セキュリティ`) | 既存語(連結) | 造語の候補(構成) |

`未認証データ` の点数が低いのは、`未認証` が記事と技術文書を合わせて 20 回、`認証データ` が 31 回しか現れないためである。左右の単位がどちらも高頻度になるという圧縮の形は、この語では成り立たない。上の閾値に届いて造語の候補になるのは残る 2 語で、`未認証データ` は下の閾値に届かない側から造語の候補になる。

## 対の検査の扱いを決めた記録

対の検査をやめる `off` と、構成の分析と、対の検査をグレーにする `gray` を同じ表で並べた結果は `../filter-choices/README.md` の対応表にある。既定を `off` にした根拠は `../../design.md` の「既定の根拠」にある。
