# 複合語の頻度フィルタの仕組み

複合語の頻度フィルタは、入力から数えた複合語と登録した見出しを引いて語を判定します。組む手順は `README.md` に、成果物の使われ方とファイルの形式は `artifacts.md` に、正解つきの語の集合と当たり方は `eval/README.md` にあります。

## 判定の区分

`judge` は語を 4 つの区分に振り分けます。既存語はコーパスか見出しにある語、グレーは稀にしか現れない語、造語の候補はどこにもない語です。文書の分野を渡したときだけ、既存語のうち文書の分野の外に偏る語を転用の候補に分けます。akunuki も同じ判定で複合名詞の候補を振り分けています。

## 入力

### Wikipedia の記事

Wikimedia が配る cirrussearch のダンプ `jawiki-20251229-cirrussearch-content.json.gz` を読みます。形式は行ごとの JSON で、投入先を書いた行と記事の行が交互に並びます。本文には平文の `text` を使い、wikitext の `source_text` は使いません。

名前空間 0 の記事をすべて採ります。情報技術の記事だけを数えると、`完了条件` や `読み手` のような一般の複合語が統計に入らず、既存語が造語の候補に見えるためです。`count --topics` を渡すと、各記事が `weighted_tags` に持つ 0 から 1000 までの話題の予測のうち、`STEM.Computing` か `STEM.Technology` が 500 点以上の記事だけを採ります。どちらで数えたかは、manifest の絞り込みの条件に残ります。

### 解析辞書の見出し

見出しの入力は SudachiDict の 2026-07-23 のバージョンで、配布元が置く `small_lex.zip` と `core_lex.zip` と `notcore_lex.zip` から取ります。full はこの 3 つを合わせたもので、akunuki が埋め込む core は `small` と `core` を合わせたものです。core にある見出しも分割単位 A で割れるなら登録の対象になるので、3 つとも読みます。各 zip は CSV を 1 つ持ち、見出しは 1 列目、品詞は 6 列目から 9 列目にあります。

akunuki が埋め込む解析辞書は core なので、full にだけある語は分割単位 A で 2 形態素以上に割れ、コーパスに現れなければ造語の候補に見えます。full の見出しは人手で採録された既存語なので、頻度によらず既存語として扱います。品詞の 1 段目が名詞の見出しを分割単位 A で割り、 2 形態素以上に割れたものを、回数から決まるバケットとは別のバケット 7 で登録します。バケットの一覧は「バケット」にあります。1 形態素の見出しは core でも full でも 1 語で、造語の候補にならないので登録しません。

固有名詞の見出しは登録しません。akunuki は固有名詞を含む連なりを候補にしないので、登録しても引かれないためです。固有名詞は登録の対象になる見出しの大半を占めるので、外すとフィルタが 2.0 MB 小さくなります。`dictionary-headwords --proper-nouns` を渡すと、固有名詞の見出しも書きます。

### 記事名とリダイレクト名

Wikipedia の記事名も人手で付けられた既存語なので、バケット 7 で登録します。`article-titles` がダンプの `title` と `redirect` のフィールドから名前を取り、解析辞書の見出しと同じ形の TSV に書きます。記事の本文は `count` が数えていますが、リダイレクト名は本文に現れないことがあるので、その分が足されます。

記事名とリダイレクト名は、全体が複合語の 1 つの区間として成り立てば採り、固有名詞を含めば採りません。区間の条件は「数え方」が本文に当てるものと同じで、複合語を成す品詞だけででき、形態素が原文で隣り合うことを指します。記号や空白や助詞を含む名前は区間にならないので、`.jpg` と `恋の掟 (漫画)` は落ちます。1 形態素の名前は、解析辞書にないカタカナと英字の連なりだけを採り、`count` がこの形をキーとして数える既定に合わせます。読むのは名前空間 0 の記事だけで、 `redirect` のフィールドも名前空間が 0 のものだけを採ります。他の名前空間の名前は分類や議論の頁を指すので、記事名になりません。

### 日本語の技術文書

Wikipedia の記事は一般の語彙を広く覆いますが、技術文書に固有の複合語は薄くなります。 `管理画面`・`読み取り専用`・`設定ファイル` のような語がこれにあたります。翻訳された公式文書と日本語で書かれた技術書を足して、その薄さを補います。

取得した文書は、`flatten` が `corpus/raw/manifest.tsv` の形式の列で変換を選んで、 1 文書 1 ファイルの平文を `corpus/text/<ソース名>/` へ書きます。原文のディレクトリの形を保ち、ファイル名の末尾に `.txt` を足します。拡張子を置き換えないのは、同じディレクトリの `a.md` と `a.mdx` が同じ名前になるのを避けるためです。

変換は形式ごとに分かれます。md と mdx は akunuki の `aku_core` で走査し、フロントマターとコードブロックとコードスパン、HTML のタグ、リンク先の URL を外します。po は `msgstr` の本文だけを取り、訳していない項目と、バージョンの記録を持つ見出しの項目を捨てます。rst はディレクティブとリテラルブロックとコメントを落とし、見出しの飾りと表の罫線も落とします。訳文のリポジトリは原文の英語をコメントに残すので、コメントは字下げした本体ごと落とします。どの形式でも、日本語の文字の比率が 0.20 に届かない段落は落とします。この値は akunuki が検査で使う下限と同じで、訳し残した英語の段落と、識別子だけを並べた表のセルがこれで落ちます。

rst の変換に pandoc は使いません。要るのは日本語の地の文だけなので rst の全機能を解釈しなくても取れるうえ、手順を通すユーザーが pandoc を別に入れずに済むためです。代わりに置いた行ごとの除去は、`include` で読み込む別ファイルを展開せず、入れ子のディレクティブは外側の 1 段だけを読みます。`include` される側の本文は、そのファイルを読んだときに取れます。MDN の `{{Glossary(...)}}` のようなマクロは Markdown の地の文なので、呼び出しの形のまま平文に残ります。マクロの引数は括弧と引用符で区切られていて、複合語を成す区間は記号で切れるので、数え方の側では語をまたぎません。

`flatten` が書いた `corpus/text/manifest.tsv` は、ソースごとの文書数と、平文のバイト数を持ちます。

### 日本語コーパス

Wikipedia の記事と技術文書を足しても、`完了条件`・`検証手順`・`対応表` のような作業文書の語彙と、セキュリティの語彙は薄いままです。この 2 つの語彙を補うために、官公庁と公的機関が公開する書き言葉を集めたコーパスを 3 つ目の入力にします。パスは `count --corpus-dir` に渡します。

コーパスはソースごとに 1 つのディレクトリを持ちます。`<ソース>/text/*.txt` が 1 文書 1 ファイルの平文で、PDF と HTML から抽出して整形してあります。目次の点線とページの印は一部に残ります。 `<ソース>/manifest.jsonl` は 1 文書 1 行の記録で、`license` と `style` を持ちます。`style` の値は `説明文` と `指示文` と `法令文` と `百科` の 4 つです。

`count --corpus-dir` はソースのディレクトリを名前の昇順に並べ、その下の `text/` の平文を技術文書と同じ文書単位で数えます。ソースの列挙はディレクトリ名で行い、`manifest.jsonl` からは文体とライセンスだけを読みます。1 ソースの中でこの 2 つの値は 1 つずつなので、記録には重複を畳んで写し、値が混ざっていれば全部を並べます。`jawiki` はダンプから数えた回数と重なる Wikipedia の平文で、`raw` は `corpus/text` が同じものを持つ GitHub の技術文書なので、この 2 つは `--exclude` で外します。成果物の manifest には、ソースごとの名前と文体とライセンスと文書数とバイト数が載ります。

`count` が書いた `corpus-stats.json` は、ソースごとの文体とライセンスと文書数とバイト数を持ちます。ライセンスは記録の文言の先頭までで、但し書きを含む全文は成果物の manifest にあります。

### 正解集合の採り先の除外

`eval/` の既存語の例は、技術文書の `owasp-top10` と `ts-survival`、日本語コーパスの `jpccert-eyes` と `ipa-websec` から採ります。頻度を数えた本文と、その頻度で測る本文を分けるため、評価用の成果物ではこの 4 ソースを `count --exclude` で外します。配布用の成果物には入れます。外すのは、技術文書の 284 文書 1,146,667 バイトと、日本語コーパスの 140 文書です。

## 数え方

### 複合語の区間

本文を句点と改行で文に切り、文ごとに分割単位 A の形態素列にします。解析には akunuki の `aku_morph::analyze_short` を呼びます。数える側と検査する側が同じ解析と同じ条件で語を割らなければ、数えたキーは検査する側の候補と当たりません。この一致が、数え方と登録の設計の多くを決めています。

形態素列から、複合語を成す品詞が原文で続く区間を切り出します。採る品詞は、名詞のうち普通名詞と固有名詞、接頭辞、接尾辞です。数詞と記号に当たった区間はそこで切れ、空白で離れた形態素も続きません。区間の長さは 2 から 5 形態素とし、3 形態素以上の区間では隣り合う 2 形態素の対も数えます。6 形態素以上の区間は全体を数えず、対だけを数えます。

空白で切れる条件には 1 つだけ例外があります。漢字を含む名詞(`読み取り`、`専用`、`呼び出し`)とラテン文字だけの名詞(`API`、`AND`)が対をなす箇所は、間に半角空白 1 つ(U+0020)を挟んでも区間を切りません。対の並びはどちらの順でもよく、`読み取り専用 API` は `読み取り専用API` の、`API 呼び出し` は `API呼び出し` のキーになります。akunuki の `unknown-compound` が同じ規則でこの対を連ね、空白を除いたキーでフィルタを引くためで、数える側が同じ規則で数えなければそのキーはフィルタに載りません。判定は akunuki の `aku_morph` が公開する関数を呼ぶので、両者の規則は 1 つの実装が持ちます。送りがなの有無は見ないので、分割単位 A でも C でも同じに働きます。ただし `済み` と `ごと` と `無し` は、`gzip 済み` のようにラテン文字の語へ接辞として続く形が正当なので、対の一方にしません。カタカナの名詞(`Azure サブドメイン`)と、漢語どうし(`侵害 成功`)と、全角空白や 2 つ以上の空白を挟む箇所は、これまでどおり空白で切れます。空白なしの隣接(`Azureサブドメイン`)は変わりません。部品の回数は、跨いだ場合も区間に現れた形態素ごとに数えます。

ラテン文字だけの名詞を含む区間は、全体と隣り合う対に加えて、その名詞で区切った日本語だけの部分区間も、それぞれ独立の区間として同じ規則で数えます。`Django認証バックエンド` は、全体の `Django認証バックエンド` と対の `Django認証` のほかに、部分区間の `認証バックエンド` のキーを持ちます。空白を跨いだ区間だけでなく、空白なしで隣接した同じ型にも当てます。akunuki の `unknown-compound` がラテン文字で区切った漢語の部分列を別に判定するので、数える側が同じキーを持たなければ当たりません。区切らなければ、ラテン文字の語が前に付いた出現の分だけ `認証バックエンド` の回数が減り、その語しか無い文書ではキーがフィルタから消えます。部分区間のキーが全体の対と同じ形になっても、1 つの区間の出現は 1 回と数えます。

形状詞は採りません。`静的解析` の `静的` と `動的計画法` の `動的` は形状詞なので、この 2 語は区間として切り出されず、部品の頻度も 0 になります。

### 解析辞書にない 1 形態素

解析辞書に見出しがないカタカナと英字の連なりは 1 形態素にまとまるので、`kubectl` と `フルユニバース` のようにこの形になる語は、2 形態素以上という区間の条件から落ちます。そこで、この形の 1 形態素も 1 つのキーとして数えます。数える側と検査する側は同じ条件を通るので、 `judge` でこの形の語を引くときは `--unknown-morphemes` を渡します。なお、 `count --count-known-only` はこの形を数えません。

### キー

区間のキーは、表層形を連ねた文字列と正規化形を連ねた文字列の 2 種類を作ります。2 つが同じなら 1 つにまとめ、違えばどちらも同じ回数で数えます。部品の頻度は区間に現れた形態素の表層形ごとに数えるので、区間の外に現れた名詞は頻度に入りません。

複合語のキーは数千万件になり、1 つのハッシュ表で持つと数 GB を占めます。そこで、表のキーが 800 万件に達したら、キーの昇順に並べた TSV へ書き出して表を空にします。数え終えたら途中の TSV を同時に読み進め、同じキーの回数を足しながら 1 つの表へ書きます。部品のキーは複合語よりずっと少ないので、最後まで表で持ちます。

### 記事の出現回数と文書数

Wikipedia の記事は出現回数で数えます。技術文書と日本語コーパスは文書単位で数え、1 文書に何度現れても 1 回とし、キーが現れた文書の数を数えます。技術文書ではナビゲーションと免責とライセンスの定型文が文書ごとに繰り返され、官公庁の文書は同じ注記と様式を繰り返します。出現回数で数えると、その定型文の複合語が高い回数を持つためです。複合語も部品も同じ数え方です。

### 語と分野の組

`count --domains` は、語と分野の組の回数も数えます。組の回数はその分野でキーが現れた記事の数で、1 記事に何度現れても 1 回です。記事の分野は話題の予測から決め、技術文書と日本語コーパスはソースから決めます。分野の区分と割り当ては「分野のフィルタ」にあります。組の回数は複合語の回数と同じ形の TSV に書き、キーの末尾に分野の番号を置きます。番号を語の後ろに置くと、キーの昇順では 1 つの語の行が隣り合います。`build` はその並びを読み進めて語ごとの総数を出せるので、数千万件の組を表に載せずに分野の割合を求められます。

## 成果物の組み方

### 3 つの入力の合算

`build` は 3 つの入力の回数に重みを掛けて足します。重みの既定は、記事の出現回数も技術文書の文書数も日本語コーパスの文書数も 1.0 で、`--counts-weight` と `--docs-weight` と `--corpus-weight` で変えられます。重みは正解つきの語の集合で当たり方を測ってから決めるもので、配布中のバージョンは測る前の単純な和です。

### バケット

重みを掛けて足した回数はバケットに丸めます。1 は 3 から 9 回、2 は 10 から 99 回、3 は 100 から 999 回、4 は 1,000 から 9,999 回、5 は 10,000 回以上です。7 は解析辞書の見出しと記事名で、同じキーが回数の側にもあれば 7 が勝ちます。照合は当たるバケットのうち最大を返すので、両方を登録しても結果は同じですが、キーの数を増やさないために `build` が 1 つにまとめます。6 は後続の作業のために空けてあり、使いません。

2 回以下の複合語は捨てます。この下限は `build --min-count` で変えられます。下限を 3 に置いてバケット 1 を残すのは、「見たことはあるが稀」という段階を持つためです。akunuki に組み込むとき、この段階の語を warn ではなく info に落とす根拠になります。

部品の頻度表にも同じ下限を当て、足した頻度が 3 に満たない部品を捨てます。この下限は `build --min-component-count` で変えられます。落ちるのは部品の比の閾値 1000 に遠く届かない部品なので判定は動かず、頻度表だけが 9.7 MB 小さくなります。

### 部品の相手の種類数

`build` は、部品の頻度表の値に、部品の出現数と並べて、前後に付く相手の種類数を 4 つ載せます。4 つは、前に外来語が付いた複合語の種類数、前に漢語が付いた種類数、後ろに外来語が付いた種類数、後ろに漢語が付いた種類数です。数えるのは、3 つの入力の回数を重み付きで足した和が `--min-count` 以上の複合語のキーで、解析辞書の見出しと記事名は数えません。キーを分割単位 A で形態素に割り、隣り合う形態素の対ごとに、左の部品には「後ろに相手が付いた」と、右の部品には「前に相手が付いた」と数えます。相手の種類は相手の表層形の字種で決め、ラテン文字かカタカナ(長音符を含む)だけなら外来語、漢字を含めば漢語とし、どちらでもない相手は数えません。この字種の判定は、akunuki の `unknown-compound` が連なりの形を見る判定と同じ文字集合です。同じ複合語は 1 種類 1 と数え、回数は見ません。3 形態素以上の複合語は隣り合う対をすべて数えます。頻度が下限に満たない部品は、種類数があっても載せません。

分割単位 A では `演算子` が `演算` と `子` に割れるので、`ビット演算子`・`シフト演算子`・`論理演算子` があれば、`演算` の前・外来語は 2、前・漢語は 1、後ろ・漢語は 3 になります。後ろの相手はどれも `子` ですが、種類数は相手の語ではなく複合語の種類で数えるためです。表層形と正規化形が違うキーは、どちらも別の複合語として数えます。値の欄と符号化は `artifacts.md` の「component_freq.fst」にあります。

種類数は、akunuki の `unknown-compound` が、複合語そのものがフィルタに無いときに、その部品がその位置でどれだけ多くの相手と結び付いているかの根拠に使う欄です。人が書いた技術書 5 冊(1.87M 字)にある漢語 1 語と外来語の連なりのうち、フィルタにない 1,754 回を外来語の相手の種類数で振り分けると、既知語になる割合は次のとおりです。

| 閾値 | 技術書で既知語になる割合 | LLM が書いた分析報告 8 本で既知語になる割合 |
|---:|---:|---:|
| 5 | 97% | 74% |
| 10 | 92% | 64% |
| 20 | 90% | 57% |

閾値 10 で技術書に残るのは `許諾プログラム`・`アドオン無効化` などで、分析報告に残るのは `スコープ是正`・`集約キー`・`盲点スイープ` などの造語です。

見出しには、分割単位 A の部品のほかに、分割単位 C で 1 語になり分割単位 A で 2 形態素以上に割れる語も載せます。`母集団`・`敵対的`・`読み取り専用` がこれにあたります。`build` は同じ複合語のキーを分割単位 C(`aku_morph::analyze`)でも割り、この形の語があれば、C の形態素列の隣り合う対から同じ規則で相手の種類数を数えて表に足します。C でも A の 1 形態素と同じ語は A の側で数えるので、足しません。語全体が C の 1 形態素になる `公開鍵暗号` には相手が無いので、見出しにしません。この語の出現数の欄は、部品の回数の TSV にその語があればその値、無ければ 0 で、部品の頻度の下限は当てません。

C の語を見出しに持つのは、検査する側が分割単位 C で解析するためです。`母集団レビュー` の境界の形態素は C では `母集団` で、A の `集団` で引くと、後ろに外来語が付く種類数は `集団` の分だけ多くなり、既知語に倒れます。`母集団` を見出しに持てば、後ろに外来語が付く複合語の種類数はその語の分だけになり、造語の候補として残ります。

### 分野のフィルタ

`domain_filter.bin` は、語がどの分野に現れるかを引くフィルタです。頻度のフィルタが語の有無だけを返すのに対し、こちらは語と分野の組で登録の有無を返します。キーは `<分野の番号><タブ><語>` の文字列で、値を持ちません。照合は分野の数だけキーを組んで引き、当たった分野を集めて返します。頻度のフィルタが持つバケットを分野の番号に使わないのは、照合が当たったバケットのうち最大の 1 つしか返さず、分野の集合を取れないためです。形式は頻度のフィルタと同じ binary fuse filter で、ヘッダーには同じ解析辞書のバージョンを書きます。分野の番号と名前の対応は `manifest.json` の `domain` の節にもあります。

#### 分野の区分

区分は 7 つの分野と、分野をまたぐ語の「一般」からなります。

| 番号 | 区分 | 元 |
|---:|---|---|
| 1 | 情報技術 | `STEM.Computing` と `STEM.Technology`、技術文書、情報技術の機関の文書 |
| 2 | その他の理工 | 残りの `STEM` |
| 3 | 文化 | `Culture` |
| 4 | 地理 | `Geography` |
| 5 | 社会 | `History_and_Society` |
| 6 | 行政 | 官公庁の説明文と指示文 |
| 7 | 法令 | 法令文 |
| 8 | 一般 | 登録される分野の数が閾値以上の語 |

Wikipedia の記事の分野は、`weighted_tags` の articletopic の予測のうち 500 点以上のものを分野の区分の対応で畳んで決めます。1 記事は複数の分野を持てます。どの区分にも当たらない予測は、実際には現れません。配布中のバージョンでは、情報技術が 31,397 記事しかなく、Wikipedia でいちばん薄い分野です。

| 分野 | 記事 |
|---|---:|
| 情報技術 | 31,397 |
| その他の理工 | 164,686 |
| 文化 | 762,478 |
| 地理 | 844,552 |
| 社会 | 249,288 |

分野を持つ記事の延べ数は 2,052,401 件で、記事の総数 1,484,267 件を上回ります。

技術文書は翻訳された公式文書と技術書なので、どのソースも情報技術とします。日本語コーパスはソースの機関と文体で決めます。文体が法令文のソースは法令とし、名前の最初の `-` までが `ipa` と `jpccert` と `jvn` と `nco` と `nicter` のどれかであれば情報技術、残る官公庁のソースは行政とします。この規則で 20 ソースは、情報技術の 9 ソース 1,885 文書と、行政の 10 ソース 3,388 文書と、法令の 1 ソース 9,267 文書に分かれます。

#### 登録の条件

語がその分野で下限以上の記事か文書に現れれば、その分野で登録します。既定の下限は 5 で、 `build --domain-min-count` で変えられます。数えるのは出現回数ではなく記事か文書の数なので、 1 記事に何度現れる語も 1 件と数えます。3 つの入力の回数は、同じ組で足してから下限に当てます。

登録される分野の数が閾値以上の語は、分野ごとの登録の代わりに「一般」の 1 つで登録します。既定の閾値は 5 で、`build --general-threshold` で変えられます。分野をまたぐ語を分野ごとに登録すると、キーがその分野の数だけ増えるうえ、どの文書の分野でも転用の候補になりません。

`build --domain-share-threshold <割合>` を渡すと、件数ではなく割合で登録します。割合は、語ごとの総数を分母、その分野の数を分子にして出します。総数は分野ごとの数を足したもので、複数の分野を持つ記事はその分野の数だけ総数に入ります。閾値以上の割合を持つ分野があればその分野で登録し、すべての分野の割合が閾値に届かない語と、閾値以上の分野が 3 つ以上ある語は「一般」で登録します。総数が 5 に満たない語は登録しません。

`--general-min-total <数>` を併せて渡すと、総数がこの数以上の語を割合を見ずに「一般」で登録します。この引数は `--domain-min-count` とも `--general-threshold` とも併せて渡せません。配布中のバージョンは件数で登録していて、割合を採らない理由は「既定の根拠」にあります。

## 判定

### 3 つの検査

`judge` は語を分割単位 A で割り、成果物を引いて区分と理由を出します。理由は辞書と高頻度と低頻度と連結と構成と部品と未登録の 7 つです。判定は 3 つの検査を順に当てます。

1. 複合語のキーでの完全一致
2. 部品の頻度の比 `min(f(X), f(Y)) / (f(XY) + 1)` と閾値の比較
3. どちらにも当たらない語の既定

完全一致では、バケット 7 なら辞書にある既存語、2 以上なら高頻度の既存語、1 ならグレーとします。部品の比が閾値を超えれば、部品はありふれているのに組み合わせがない語として造語の候補とします。3 つ目に落ちた語も造語の候補とします。

複合語のキーは、`count` が表層形を連ねた形と正規化形を連ねた形の両方を数えるので、照合も両方を引きます。一方、部品の頻度は表層形だけで引きます。`count` が部品を表層形で数えているため、正規化形で引くと別の語の頻度を拾うからです。2 つ目の検査に来る語は 1 つ目の完全一致を外れているので `f(XY)` が 0 になり、比は部品の最小の頻度そのものになります。

部品の比の閾値の既定は 1000 で、`judge --threshold` で変えられます。閾値は区分を変えず、造語の候補の理由を部品と未登録に分けるだけです。

カタカナだけで続く語のように分割単位 A で 1 形態素になる語は、`judge --unknown-morphemes` を渡せば完全一致で引けます。渡さなければ、この形の語はどのキーでも引かれず、造語の候補に落ちます。

### 3 形態素以上の語の検査

`judge --concatenation` は、1 つ目と 2 つ目の間に、3 形態素以上の語への検査を挟みます。値は 4 つあります。

| 値 | 検査 |
|---|---|
| `off`(既定) | 何も挟まない |
| `established` | 隣り合う 2 形態素の対を引き、対がすべてバケット 2 以上なら既存語の連結とする |
| `gray` | 同じ対の検査で、対がすべて高頻度ならグレーとする |
| `composition` | 対の検査を構成の分析に置き換える |

既定が `off` なのは、LLM の造語が句を複合語に圧縮して作られることが多いためです。 `未認証のデータ` が `未認証データ` に、`攻撃的なセキュリティ` が `攻撃的セキュリティ` になる形で、よく使う部品を新しくつないだものなので、隣り合う対はどれも高頻度になります。対の検査は対がすべて高頻度な語を既存語とするので、圧縮された造語をちょうど既存語に倒します。

### 構成の分析

語を分割単位 A の形態素列にし、左右 2 つに分ける分割をすべて列挙します。`未認証データ` なら `未` と `認証データ`、`未認証` と `データ` の 2 通りです。分割ごとに左右の頻度の小さい方 `min(f(左), f(右))` を出し、その最大値を語の点数とします。左右に立つのは 1 形態素か、フィルタに登録のある複合語です。

左右の頻度は 2 つの表から取ります。1 形態素の頻度は部品の頻度表にあります。複合語の回数は `count` が書いた回数の TSV から読み、Wikipedia の出現回数と技術文書の文書数を `build` の既定の重みで足して、和が 3 以上のキーだけを表に載せます。回数の TSV のパスは、`judge` に `--counts-dir` と `--docs-counts-dir` で渡します。解析辞書の見出しでありながら回数の TSV にない語は頻度がわからないので、その語を左右に持つ分割は点数に使いません。

点数は 2 つの閾値で区分に分かれます。上の閾値(既定 300、`--upper-threshold`)以上の点数を持つ語は圧縮された造語の候補とし、理由を構成と書きます。下の閾値(既定 100、 `--lower-threshold`)以上でそこに満たない点数はグレーとします。疎さでコーパスから落ちた既存語でありうるためです。下の閾値に満たない点数は、部品の側にも手掛かりがないので、理由を未登録と書いて造語の候補とします。

2026-09-07 の計測では、回数の表を持つ `judge` は最大 RSS 891,344 kB で 6.2 秒かかり、表を持たない `judge` は 144,272 kB で 0.04 秒です。

### 転用の候補

`judge --document-domain <分野>` は、完全一致で既存語と決まった語について分野の集合を引きます。集合が一般か文書の分野を含めば既存語のままとし、特定の分野だけで文書の分野を含まなければ転用の候補とします。理由の列には現れた分野を書きます。

```
cargo run --release -- judge --artifacts-dir ../variants/evaluation \
    --document-domain 情報技術 参照資料 公開鍵暗号
参照資料	転用の候補	分野(その他の理工・文化・地理・社会)
公開鍵暗号	既存語	辞書
```

集合が空の語は既存語のままにします。集合が空になるのは、どの分野でも登録の下限に届かなかったからであり、語が別の分野に偏る証拠にはなりません。

## 既定の根拠

引数の既定は、`eval/` の正解つきの語の集合で測って決めました。造語の再現率は、語そのものが存在しない 129 語のうち、造語の候補と判定した語の割合です。意味の転用の再現率は、実在する用語を別の意味で使った 19 語で同じように出します。既存語の誤検出率は、既存語の例 563 語かセキュリティの既存語の例 347 語のうち、造語の候補と判定した語の割合です。

行ごとにどちらの集合を母数にしたかと、測ったコマンドと数は、記録の列が指すフォルダにあります。混同行列の読み方と配布中の成果物の当たり方は `eval/README.md` にあります。選択ごとの既定と根拠は次のとおりです。

| 選択 | 既定 | 根拠 | 記録 |
|---|---|---|---|
| 数える記事 | 名前空間 0 の全記事 | 情報技術の記事だけでは一般の複合語が統計に入らず、既存語が造語の候補に見える | `archive/input-sources/` |
| 技術文書と日本語コーパス | 足す | 技術文書は既存語の誤検出率を 6.7 ポイント下げ、日本語コーパスはセキュリティの既存語の誤検出を 9 語から 7 語に減らす | `archive/input-sources/` |
| 法令 | 1947 年以降の口語体だけ | 文語体の法令は解析辞書に合わず、法令の有無は誤検出率を動かさない | `archive/input-sources/` |
| 解析辞書にない 1 形態素 | 数える | 数えないと広げた既存語 832 語のうち 365 語が造語の候補に倒れ、数えると 130 語に減って造語の再現率は落ちない | `archive/filter-choices/` |
| 回数の下限 | 3 | 5 にするとフィルタは 8.3 MB 小さくなるが、稀な語を info に落とす根拠になるバケット 1 が消える | `archive/filter-choices/` |
| 固有名詞の見出し | 登録しない | akunuki が候補にしないので登録しても引かれず、外すと 2.0 MB 小さくなって既存語の誤検出は 1 語しか増えない | `archive/filter-choices/` |
| 部品の頻度の下限 | 3 | 頻度表が 9.7 MB 小さくなり、判定は 1 語も動かない | `archive/filter-choices/` |
| 隣り合う対の連結の検査 | `off` | 対の検査は圧縮された造語を既存語に倒し、やめると造語の再現率が 5.5 ポイント上がる一方で既存語の誤検出率は 3.1 ポイントしか上がらない | `archive/filter-choices/` |
| 部品の比の閾値 | 1000 | 造語と既存語で理由が部品になる割合の差は 1000 から 3000 で 30 から 35 ポイントと変わらず、その範囲で造語を最も多く残す | `archive/filter-choices/` |
| 構成の分析の閾値 | 上 300・下 100 | 対の検査より造語の再現率が高い組のうち、既存語の誤検出率がいちばん低い | `archive/composition/` |
