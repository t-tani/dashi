# dashi

dashi は、akunuki が引く言語資源と、それを作って検証する工程をまとめたリポジトリです。名前は、灰汁を抜く(akunuki)前に取る出汁の意です。

## 成果物

### 意味分類表

意味分類表は、語を引くと分類番号が返る TSV です。これで、語が物を指すのか事柄を指すのかを機械で判定できます。1 つの語が複数の中項目に当たれば、分類番号も複数返ります。

分類番号の桁の読み方と、部門の分かれ方は次のとおりです。

```
分類番号の形

    1 . 4 5 0 0
    ^   ^ ^
    |   | +-- 中項目の一の位
    |   +---- 中項目の十の位。これが部門
    +-------- 表の種類。名詞は 1、動詞は 2

部門

    1 関係、2 主体、3 活動 ...... 事柄や関係を指す
    4 生産物、5 自然物 .......... 物を指す

名詞は 5 部門 43 中項目、動詞は 1 と 3 と 5 の 3 部門 23 中項目に分けます。
```

現代の語の使われ方に沿った分類表が既存の言語資源にないので、LLM に判定させて作っています。表と、見出し語と判定の記録は `semantic-class/noun/` と `semantic-class/verb/` にあります。名詞と動詞に共通の生成の工程は `semantic-class/pipeline/` の Python が持ちます。入力から表までの手順は `semantic-class/pipeline/README.md` にあります。

### 複合語の頻度フィルタ

複合語の頻度フィルタは、見慣れない複合語が世の中で使われている語なのか、その場で作られた語なのかを分けます。分野を添えて引けば、別の分野から持ち込んだ語も見つかります。

引いた結果は次のように読みます。回数は、フィルタの 3 つの入力を合わせた数です。

```
「幽霊参照」を判定する

    freq_filter.bin ....... 登録なし
    component_freq.fst .... 幽霊 8,224 回、参照 43,056 回
                            部品はありふれているのに、つないだ形が現れない
    => その場で作られた語の候補

「未知語」を情報技術の文書で判定する

    freq_filter.bin ....... 登録あり。世の中で使われている語
    domain_filter.bin ..... 登録はその他の理工だけ。情報技術にない
    => 別の分野から持ち込んだ語の候補
```

`freq_filter.bin` は複合語のキーと、どれだけ使われているかの区分を持ちます。`component_freq.fst` は複合語の部品ごとの頻度表で、`domain_filter.bin` は語と分野の組です。

回数を数える入力は 3 つで、Wikipedia 日本語版の全記事と、日本語の技術文書と、日本語コーパスです。日本語の技術文書は翻訳された公式文書と技術書からなり、日本語コーパスは官公庁と公的機関が公開する書き言葉を集めたものです。Wikipedia の記事は出現回数で数え、残りの 2 つは語が現れた文書の数で数えます。この 3 つに加えて、SudachiDict の見出しと Wikipedia の記事名を、人手で付けられた既存語として登録します。

フィルタを組む工程は `compound-frequency/corpus-tool/` の Rust が持ちます。ソースごとのライセンスと文書数は `compound-frequency/design.md` に、入力から成果物までの手順は `compound-frequency/README.md` にあります。
